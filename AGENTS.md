# Правило границ работы

Весь цикл задачи (пути, доступ с .110 по ssh, сборка, симулятор, проверка,
коммит, установка на iPhone) — `AGENT-CYCLE.md`. Читать до первой правки.

## Нативные компоненты: постоянное правило владельца

Если владелец просит «нативный», «оригинальный» или «системный» компонент,
оставлять чистый SwiftUI-компонент без собственных `tint`, `background`,
`overlay`, `scaleEffect`, рамок, материалов и имитаций — если владелец прямо
не попросил именно эту настройку.

Нельзя называть компонент полностью системным, когда на нём остаётся хотя бы
одна такая визуальная настройка. При сомнении оставить чистый системный вид.

Работа ведётся только в `/Users/max/Проекты/TaskFlowNativeBuild`.

Исходный файл можно изменять только когда он указан в строке со статусом
`IN_PROGRESS` в `AGENT-WORK-SCOPES.md`. Всё вне такой строки неизменно.

## Проверка в симуляторе iOS: через XCUITest, не через ручной тап по скриншоту

Дойти до нужного экрана для проверки — через временный XCUITest, который
ищет элементы по `accessibilityIdentifier`/`label` (`app.buttons["..."]
.tap()`, `app.staticTexts["..."].tap()`), не через screenshot-инструмент
симулятора с ручным пересчётом координат под тап. У `tap`/`swipe` координаты
в points, а скриншот отдаётся в пикселях retina (обычно ×3) и часто ещё
масштабирован для показа — пересчёт почти всегда промахивается мимо нужного
элемента. Тот же временный XCUITest снимает `XCTAttachment(screenshot:)` для
итоговой визуальной приёмки — второй инструмент для этого не нужен.

Владелец 29.09.2026, после серии промахов мимо элементов на кадрах симулятора
в одной из сессий: «ты заебал, когда ты уже начнёшь это делать нормально».


## Приёмка UI на физическом iPhone

Изменения поведения интерфейса, чата, анимации, прокрутки и обновления данных
проверять точным XCUITest в симуляторе и на **физическом iPhone**. Для плавности
измерять hitches, CPU и память в представительном сценарии на устройстве;
preview обязан включать настоящий проверяемый механизм. Сохранить xcresult,
кадры и метрики, затем вернуть приложение к обычному запуску. Симулятор,
успешная установка и зелёная сборка физическую приёмку не заменяют.

Полный обязательный порядок, экономный цикл сборок и команды —
`AGENT-CYCLE.md`, раздел 7 «Приёмка на устройстве» (указание владельца
11.10.2026). Для правок только документации запуск приложения не требуется.

## Роли TaskFlow на маке: хост и песочница (с 15.10.2026)

Роль-разработчик по задачам проекта «TaskFlow Native iOS» работает на маке через
хост `taskflow-host` (машина `macbook`), а не в отдельной копии
`~/Проекты/TaskFlowDeveloper` — та упразднена вместе со ssh-шлюзом.

- Рабочая копия роли — git worktree этого репозитория в `.worktrees/<task_id>`,
  ветка `roles/<task_id>`, создаётся от текущего `main`. Отдельной копии,
  отстающей от main, больше нет.
- Команды идут под `sandbox-exec`: доступен только этот репозиторий; домашний
  каталог, ключи и соседние проекты закрыты. Симулятор — только iPhone Air iOS 27.
- Сборка (DerivedData и пакеты — внутри корня, иначе песочница не пустит):

```bash
xcodegen generate && xcodebuild -project TaskFlow.xcodeproj -scheme TaskFlow -sdk iphonesimulator -scmProvider system -IDEPackageSupportDisableManifestSandbox=YES -destination 'platform=iOS Simulator,id=9FF78D89-EE84-4914-AA56-D0A72D1AF43A' -derivedDataPath .worktrees/_derived 'OTHER_SWIFT_FLAGS=$(inherited) -disable-sandbox' build
```

  `-IDEPackageSupportDisableManifestSandbox=YES` и `-disable-sandbox` отключают
  только вложенные песочницы SwiftPM и макросов Swift: macOS не даёт запустить
  их внутри песочницы хоста. Проверено 16.10.2026: BUILD SUCCEEDED за ~7 мин. Наружная
  песочница остаётся.
- Результат — коммит в ветку `roles/<task_id>` и `git push` (операция хоста
  `git_push`): работа уходит в общий репозиторий, вливает её владелец.

## Режим подсказок: новая функция — новая подсказка (владелец 16.10.2026)

В приложении есть пошаговые подсказки (Настройки → «Подсказки»):
затемнение, подсвеченный элемент, окошко с объяснением и ветками выбора.

- Добавил заметную функцию — добавь подсказку в той же работе: повесь на
  элемент `.hintAnchor(HintAnchorID.…)` и опиши шаги в
  `Sources/DesignSystem/Hints/HintScenarios.swift` (новый сценарий или шаг в
  существующем).
- Пункты системного меню (`Menu`) подсветить нельзя — подсвечивается кнопка
  меню, а в тексте говорится, какой пункт выбрать.
- Текст подсказки — только про то, что приложение реально делает сейчас.
- Проверка: юнит-тест хода сценария в `Tests/HintCenterTests.swift`.

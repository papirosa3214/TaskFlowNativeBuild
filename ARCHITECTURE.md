# TaskFlow Native — архитектура и правила совместной работы

Нативный клиент TaskFlow на SwiftUI. Заменяет Capacitor-обёртку (`ios/`), сервер
(`server/`, Fastify+SQLite :3001) и его API остаются как есть — переписывается
ТОЛЬКО клиент.

Цель: вид и поведение один-в-один с текущим вебом, включая собственную экранную
клавиатуру (в нативе — через `inputView`, то, во что упирался веб-вариант).

## Где что лежит

- `native/project.yml` — описание Xcode-проекта для xcodegen (правит ТОЛЬКО каркасный исполнитель)
- `native/Sources/App/` — точка входа, корневая навигация, таббар
- `native/Sources/DesignSystem/` — токены (цвет, шрифт, отступы) и базовые компоненты
- `native/Sources/Core/` — модели, APIClient, сессия, сторы, форматтеры
- `native/Sources/Features/<Экран>/` — по папке на экран: вьюхи и вью-модели только этого экрана
- `native/Sources/Keyboard/` — своя экранная клавиатура (inputView)
- `native/Resources/` — Assets.xcassets, Info.plist, entitlements, шрифты
- `native/Widgets/` — виджеты и Live Activity (перенос из `ios/App/TaskFlowWidgets`)
- `native/spec/` — спецификации, снятые с веб-версии: источник истины по виду и поведению

Код живёт и правится ТОЛЬКО на MacBook, в `~/Проекты/TaskFlowNativeBuild` —
см. `CLAUDE.md` в корне этой папки. Копия на .110 нерабочая, не источник
истины; синка между машинами больше нет — старый `scripts/sync-build.sh` тянул
исходники с .110 поверх Мака с `rsync --delete` и без предупреждения затирал
всё, что было правлено здесь (так и случилось 03.09.2026, скрипт удалён).
Вторая копия проекта на Маке (`~/Проекты/TaskFlow`) — чужая, не трогаем.

## Технические решения

- **SwiftUI**, минимальная версия iOS 18.0 (устройство — iPhone Air на 26.5; порог занижен
  сознательно, чтобы не упереться в доступность API, новые вещи включаем через `#available`).
- **Проект генерится xcodegen** из `project.yml`. Причина: несколько исполнителей пишут
  параллельно, и общий `project.pbxproj` был бы постоянным источником конфликтов —
  xcodegen собирает таргет из содержимого папок, добавление файла ничего общего не трогает.
- **Данные:** `@Observable`-сторы поверх `APIClient` (async/await, URLSession). Реалтайм —
  тем же каналом, что у веба (см. `spec/API.md`).
- **Bundle id** нативного: `com.maksim.taskflow.native` — отдельно от Capacitor-сборки
  (`com.maksim.taskflow`), чтобы оба приложения стояли на телефоне одновременно и их
  можно было сравнивать экран в экран.

## Правила, чтобы исполнители не мешали друг другу

1. **Один файл — один автор.** Свой экран пишешь только в своей папке под `Features/`.
2. **Общие файлы правит только каркасный исполнитель:** `project.yml`, всё в `Core/`,
   `DesignSystem/`, `App/`. Нужна правка в общем — не лезь сам, напиши об этом в отчёте,
   оркестратор соберёт правки и отдаст владельцу файла.
3. **Вид берётся из `spec/`**, а не из головы и не из веб-кода напрямую: числа уже сняты.
   Расходится спека с кодом — верить коду и сказать об этом в отчёте.
4. **Ничего не собирать самому** — сборка идёт централизованно через `scripts/sync-build.sh`,
   иначе исполнители дерутся за Мак и за устройство.
5. Веб (`src/`), сервер (`server/`) и Capacitor (`ios/`) — не трогать вообще.

# Диагностика UI TaskFlow iOS без симулятора

## Граница проверки

Прямое указание владельца 25.10.2026 отменяет прежний обязательный шаг «собрать → открыть экран → снять кадр». Правила — AGENT-CYCLE.md и AGENTS.md в каноническом репозитории /Users/max/Проекты/TaskFlowNativeBuild.

Не трогать симулятор самостоятельно: не собирать под него, не открывать, не устанавливать и не запускать приложение, не выполнять навигацию, кадры, видео, UI-тесты или unit-тесты через iOS Simulator. Только отдельное прямое поручение владельца на конкретную проверку позволяет это сделать. Сложность бага и общее поручение «исправить» разрешением не являются. UI-тесты требуют отдельного согласия на конкретный тест.

## Работа с жалобой

1. Прочитать описание буквально: какой экран, что владелец видит и какое изменение просит. При существенной неоднозначности уточнить. Предоставленный владельцем кадр можно изучить, самостоятельно добывать кадры в симуляторе не нужно.
2. Сначала спросить graft по симптому, затем точечно читать найденные file:line. Поиск вручную — только по тому, что граф не покрыл. Граф может отставать: сверяться с актуальным исходником.
3. Выяснить механизм, исходные иконки/подписи/цвета и историю изменения. Не менять смежные решения по собственной инициативе.
4. До правки записать точные файлы в IN_PROGRESS в AGENT-WORK-SCOPES.md.
5. Для изменения логики — целевой unit-тест без симулятора с обязательным RED → GREEN. Если существующий тест требует симулятор, назвать ограничение, не запускать автоматически. Декоративные изменения — просмотр diff и сторож дизайн-системы, без искусственных тестов по тексту исходника.
6. Сохранить результат и ограничения проверки в docs/. Не утверждать визуальную приёмку без оценки владельца.

Если владелец отдельно поручает проверку на симуляторе, выполнять только её в заданных границах; это не разрешает UI-тесты. По умолчанию визуальная оценка остаётся за владельцем.

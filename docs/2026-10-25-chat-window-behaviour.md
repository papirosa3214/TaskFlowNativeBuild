# Окно чата с ролями: разбор поведения — 25.10.2026

## Итог

Правки кода **откачены по просьбе владельца** (25.10.2026, вечер): правка
рендера текста ответа роли изменила вид шрифта, и чат стал выглядеть иначе.
Ниже остаётся разбор — что в окне чата оказалось не так и что предлагалось
чинить. Ничего из перечисленного сейчас в коде не применено.

Коммит с правками: `272f9219`, откачен коммитом `revert`.

## Задача

Владелец (25.10.2026): «посмотреть, как работает сам чат… окно, где уже ведётся
переписка с ролями… чтобы оно по одной логике и вполне нормально окно себя
вело, когда идёт разговор, когда пишется текст модели… чтобы ничего там резко
куда-то не уходило, не прилипало».

Эталон подхода — работа Клод-кода от 15.10.2026 (сессия с образцом чата из
другого приложения): сверка с его решениями, проверки без устройства, отчёт и
строка в реестре.

Скиллы, по которым шла сверка: `swiftui-performance` (инвалидации, лента,
идентичность, работа в `body`), `swiftui-expert-skill` (правила SwiftUI:
постоянное число вьюх на элемент списка, стабильная идентичность), плюс
документация Apple по `ScrollPosition.isPositionedByUser` и
`defaultScrollAnchor(_:for:)`.

## Что нашлось в окне чата

1. **Лента переставала следить за хвостом навсегда.** Положение решалось по
   `chatScrollPosition.isPositionedByUser` (`RoleChatsScreen.swift:1580`) — флаг
   SwiftUI, который ставится один раз и навсегда: после первого прокручивания
   пользователем якорь роста становился `nil`, и новые ответы роли переставали
   попадать в кадр. Кнопка «вниз» и отправка двигали ленту один раз, но режим
   слежения не возвращали.
2. **Лента уезжала вниз при росте любой строки.** Пока флаг не выставлен,
   `defaultScrollAnchor(.bottom, for: .sizeChanges)` пере-анкорил всю
   переписку при изменении высоты любого ряда — в том числе при переходе к
   конкретному сообщению (`scrollTo(id:)`).
3. **Ответ, только что показанный живым пузырём, проявлялся заново.** В момент
   подмены живой пузыря готовым сообщением (`RoleChatsScreen.swift:2280`) весь
   текст становился прозрачным и печатался второй раз — мигание в конце хода.
4. **Пузырь схлопывался при смене состава пунктов.** Pacer сопоставлял тексты по
   порядковому номеру среди текстовых пунктов (`RoleChat.swift`, `ingest`).
   Сервер меняет состав пунктов при закрытии хода (шаги и ответ собираются в
   один пункт) — сравнивались разные тексты, показанный текст обнулялся,
   высота пузыря падала, лента прыгала вверх, ответ печатался заново.
5. **Квадратичный поиск по истории** на каждом проходе тела: `replyContext`
   искал исходное сообщение линейным поиском для каждой строки ленты.
6. **Источники скачков высоты ленты, которые не трогали:** полоса рабочего плана
   над лентой (`ChatWorkPlanStrip` — появляется, исчезает, разворачивается,
   меняет высоту ScrollView), подсказки `@`, список вложений, рост окна
   размышлений до 132 pt, замена живого пузыря готовым сообщением (у готового
   подвал с действиями, у живого его нет).

## Что предлагалось сделать (откачено)

- Явная политика слежения за хвостом (`ChatTailPolicy`, чистая логика): слежение
  выключается, когда пользователь ушёл читать историю, и возвращается, когда он
  у нижнего края; решение принимается по свежей геометрии, чтобы не залипать.
- Отмена повторного проявления сообщения, которое только что показал живой
  пузырь.
- Перенос показанного текста в pacer'е по общему префиксу — пузырь больше не
  схлопывается.
- Индекс сообщений по id вместо линейного поиска по истории.

Проверки, которые были на these правки (без симулятора): RED на прежнем
поведении — 7 проверок падали (возврат к хвосту, залипание, порог отпускания),
GREEN — 14 из 14; pacer — RED 1 падение на коде из HEAD, GREEN 3 из 3; сторож
архитектуры окна чата — 4 из 4; сборка под iOS Simulator SDK (arm64, без
запуска) — успешно.

## Что не трогали и почему

- **Рендер текста ответа роли.** Правка кегля и веса выделения изменила вид
  шрифта — владелец попросил откатить (25.10.2026). Возможная причина: явный
  `.fontWeight(.bold)` без явного кегля меняет оптический размер и начертание
  системного шрифта относительно прежнего `.font(TFFont.body)`.
- **Высота строки в конце хода.** Готовое сообщение получает подвал с
  действиями, у живого пузыря его нет — при подмене высота растёт, и лента
  смещается. Чинится либо резервированием места под подвал в живом пузыре,
  либо анимацией перехода; оба варианта меняют вид окна.
- **Полоса рабочего плана, подсказки и вложения над/под лентой** — переменная
  высота меняет высоту ScrollView, и лента прыгает. Лечится переносом полос из
  VStack ленты (в overlay или safeAreaInset) — это тоже изменение вида.
- **Перехват тапа по фону ленты** (`.onTapGesture` на ScrollView): по
  исходнику не доказывается, что он мешает ссылкам и выделению текста.
- **Вложенные списки по `\.offset`** (сегменты живого пузыря, блоки markdown,
  пункты чек-листа): смена id меняет состояние ячеек.
- **Стоимость кадра при проявлении** (свой `TimelineView` на каждый блок,
  пересборка `Text` на каждом кадре) — отдельная работа по производительности.

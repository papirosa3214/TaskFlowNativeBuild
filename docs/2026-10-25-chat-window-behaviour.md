# Окно чата с ролями: разбор без правок — 25-26.10.2026

## Итог

**Правки в коде откачены по просьбе владельца** (26.10.2026): «убери всё
наше лишнее… пусть будет нативная хрень, всё как задумано оригинально. Я
хочу посмотреть, как это в оригинале выглядит». Код окна чата возвращён к
состоянию до работы (коммит `f2a4e86a`).

Что было сделано и откачено: политика слежения за хвостом (`ChatTailPolicy`),
компенсация и «доводка до хвоста», вывод текста ответа по словам (очередь
букв), индекс сообщений по id, перевод позиции прокрутки на идентификатор,
правка начертания выделения в `RoleReplyMarkdown`, диагностические логи в
приложение. Всё это — в истории коммитов, если понадобится.

## Что нашли (разбор, без правок)

1. **Положение ленты ведёт `ScrollPosition.isPositionedByUser`** — флаг SwiftUI,
   который ставится один раз и навсегда: после первого прокручивания
   пользователем лента перестаёт следить за хвостом (новые ответы роли не
   попадают в кадр), а до первого прокручивания рост любой строки
   пере-анкорит всю переписку к низу (`defaultScrollAnchor(.bottom, for:
   .sizeChanges)`).
2. **Содержимое ленты пересобирается и усыхает на сотни-тысячи пунктов** при
   подмене живого пузыря готовым сообщением: разбор markdown меняется, окно
   размышлений исчезает, появляется подвал с действиями. Смещение при этом
   остаётся прежним — лента оказывается либо в пустоте, либо с растущим
   ответом под нижним краем.
3. **Готовое сообщение показывается вторым экземпляром**: текст, уже
   показанный живым пузырём, в ленте проявляется заново.
4. **Квадратичный поиск по истории** в каждой строке ленты (`replyContext`).
5. **«Жирное» в ответе роли**: `.font(TFFont.body)` перебивает вес, и выделение
   выходит мельче обычного текста. `RoleReplyMarkdown` — общий компонент
   (больше 30 мест), правка начертания меняет вид всего приложения.
6. **Высота содержимого «дышит»** на пункты (десятки колебаний за печать) —
   лента на это реагировать не должна.

## Чем проверялось

Диагностика в приложение (писала в файл контейнера, забирался с телефона
командой `devicectl device copy from`, без root) дала числа: смещение,
высоту содержимого, расстояние до хвоста, размер области ленты и нижний
отступ. По этим числам и была названа причина; без лога пришлось бы гадать.
Сейчас диагностика тоже убрана — код в исходном виде.

## Что осталось не тронутым

- Высота строки в конце хода (у готового сообщения подвал с действиями, у
  живого пузыря его нет).
- Перехват тапа по фону ленты (`.onTapGesture` на ScrollView) — по исходнику
  не доказывается, что он мешает ссылкам и выделению текста.
- Вложенные списки по `\.offset` (сегменты живого пузыря, блоки markdown,
  пункты чек-листа).
- Стоимость кадра при проявлении: свой `TimelineView` на каждый блок,
  пересборка `Text` на каждом кадре.

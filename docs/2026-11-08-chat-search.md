# Поиск по чатам

Владелец, 08.11.2026: «А поиск бы обязательно ещё бы сделал там» — в боковой
панели чатов, рядом с ролями и групповыми комнатами.

Поиск один на всё: личные комнаты ролей, групповые и комнаты задач в архиве.
Ищется сразу по трём местам — название комнаты (или задачи/проекта), имя
собеседника и текст живой переписки.

## Сервер

`GET /api/chats/search?q=…&limit=30` (файл `server/src/routes/chats.ts`):

- запрос короче двух символов — пустая выдача;
- слова соединяются через И, как в `/api/search`: «подрядчик аудит» находит
  «Договор с подрядчиком по аудиту»;
- регистр не важен и для кириллицы: сравнение идёт через уже существующую
  SQL-функцию `lower_uni` (`routes/search.ts`), потому что встроенный
  SQLite `LOWER()` кириллицу не складывает;
- служебные строки (`message_type = 'system'`) в поиск не идут;
- выдача фильтруется тем же `isMember`, что и список чатов, — поиск не
  показывает комнату, которую человек не открыл бы и руками;
- в каждой находке — `chat_id`, `title`, `subject`, `hit_text` (последнее
  живое сообщение с самым длинным словом запроса, до 240 знаков), `hit_at`.

## Клиент

- Иконка `magnifyingglass` сверху боковой панели комнат
  (`ChatRoomsPanel`, `AccessibilityIdentifier` — `chats.rooms.search`).
- Экран `ChatSearchScreen` (маршрут `AppRoute.chatSearch`): системный
  `.searchable`, живой запрос с паузой 250 мс, ответ применяется только для
  последнего введённого текста; тап по строке открывает чат.

## Проверки

- `server/test/chatSearch.test.ts` — 4 теста: находит по тексту сообщения,
  служебные строки не выдают комнату, находит по названию и по имени
  собеседника, кириллица в другом регистре и короткий запрос.
- `npx tsc --noEmit` — чисто.

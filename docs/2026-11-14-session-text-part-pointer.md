# Сессия: вторая текстовая часть не подменяет первую (14.11.2026)

Регрессия опубликованного `f4f511a3`. Только сессии; чаты ролей не тронуты,
разбор разметки по-прежнему на сервере.

## Что было сломано

`SessionLiveTurn` держал один указатель `textItemIndex` — «пункт текста текущего
сообщения». Указатель переиспользовался при любом следующем куске текста, если
в пункте уже лежал текст: между кусками не проверялось ничего. Поэтому
последовательность **text → thinking → text → message_end** в одном сообщении
давала две потери:

1. второй текстовый кусок записывался в пункт первого (`items[0] = .text(...)`),
   первая часть исчезала;
2. порядок ломался: пунктов становилось два (текст, размышление), а не три,
   и `message_end` дописывал хвост в тот же единственный пункт текста.

Та же беда с `message_end`: хвост клался в «показанный сейчас пункт текста»
без проверки, к какой части сообщения он относится.

## Что говорит сервер (проверено по коду .110, не по догадке)

`server/src/runtime/ownerSessionEvents.ts`, `normalizePiEvent`:

- `message_update` / `text_delta` → `assistant_text_delta` с payload
  `{ delta, contentIndex, text?, blocks? }`; `text` — **весь текст части с
  номером `contentIndex`** (`partText(message, contentIndex, "text")`).
  Разные части одного сообщения различаются именно номером: Pi кладёт
  размышление, текст и вызовы инструментов отдельными элементами `content`.
- `message_update` / `thinking_delta` → `assistant_thinking_delta` с тем же
  `contentIndex`.
- `message_end` → payload `{ message, text?, blocks?, thinking? }`, где `text` —
  текст **последней** текстовой части сообщения (`[...parts].reverse().find(part.type === "text")`),
  а `thinking` — последней части размышления.
- Текстовую часть, которая начинается как служебный конверт
  (`{"schema_version"…}`), сервер кусками не шлёт вовсе: она приходит целиком
  готовой разметкой в `message_end`.

Вывод для клиента: номер части — единственный признак «новая часть или
продолжение», и в `message_end` нужно понимать, чей это хвост.

## Правка

`Sources/Features/Sessions/SessionLiveTurn.swift`:

- вместо `textItemIndex: Int?` — `textPart: TextPart?` (`index` пункта + номер
  части `contentIndex` у сервера);
- `assistant_text_delta` переиспользует пункт только если это та же часть
  (номер совпал или сервер номера не прислал — старый сервер) **и** пункт
  остаётся последним в ходе; иначе текст встаёт новым пунктом. Так
  `text → thinking → text` даёт три пункта в правильном порядке;
- `message_end` берёт номер последней текстовой части из `payload["message"]`
  (`lastTextPartIndex`) и дописывает хвост в показанный пункт только для той же
  части; для другой части (её держали конвертом) хвост встаёт своим пунктом;
- на конце сообщения указатель сбрасывается, как раньше: текст следующего
  сообщения — новый пункт;
- добавлен `JSONValue.sessionInt` — номер части приходит числом JSON.

Разметка по-прежнему только серверная: хвост кладётся лишь вместе с `blocks`
(`register`), иначе показанное размеченное начало не подменяется. Идентичность
хода (`d0a063ef`), область разметки (`5951f4fa`) и путь подготовленной разметки
экрана (`b4cf8ac3`) не менялись.

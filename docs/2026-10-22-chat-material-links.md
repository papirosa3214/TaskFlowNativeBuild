# Материалы чата открываются внутри TaskFlow — 22.10.2026

## Причина

В сообщении со скриншота настоящий документ Библиотеки существовал (`aae18cc4-1dcc-4ea9-80a9-ee4b0e5ea9ad`), но `role_envelope_json.artifacts` содержал `kind=artifact` и голый UUID. Рендер материалов делал кликабельными только http/https. Файлы под скрепкой — другой механизм: системный просмотрщик iPhone, который не обеспечивает рендер TaskFlow.

## Изменения

- `taskflow_chat_share_material(note_id, caption?)` доступен ролям через общий каталог и обычный универсальный шлюз. Проверяет заметку через существующий API от имени роли и сам отправляет в исходный чат карточку «Открыть в TaskFlow», связанную с сообщением владельца. Новых копий, файлов и вложений нет.
- Для нового материала роль сначала использует существующий `taskflow_doc_write` (Библиотека/Knowledge Base либо документация проекта), затем отправляет заметку. `taskflow_doc_write` теперь возвращает готовый `material` с `note://<id>` для sections.materials/artifacts, а не только ID. Скрепка остаётся для скачивания файлов.
- iOS преобразует `note://<UUID>` в существующий `AppRoute.noteEditor`: чтение оригинала тем же экраном, что из Библиотеки. Это действует в строках «Материалы» и в карточке виджета. UUID из старых материалов kind=document/artifact тоже открывается как заметка.
- Ссылки на задачи ведут в существующую карточку. http/https остаются внешними. Локальные пути и file:// не выдаются за доступный документ. Никаких публикаций файлов сервера в интернет.

## Проверки

- 4 XCTest логики маршрутизации через отдельный SwiftPM-пакет с точными копиями исходника resolver и теста: RED на прежнем http/https-предикате, GREEN после исправления; дополнительный RED/GREEN для реального legacy kind=artifact. Это тесты Foundation на Mac, не сборка всего iOS-приложения.
- Сервер: 4 теста share/doc_write + 8 существующих голосового шлюза PASS. Проверены реальный invoke, привязка к исходному сообщению, отсутствие вложения, отказ на отсутствующую заметку, контекст чата, готовая ссылка после doc_write. Тест нового инструмента падал на предыдущем коде; отдельно ответ doc_write проверен RED на исходном HEAD.
- TypeScript --noEmit PASS. Swift parse трёх изменённых файлов PASS. xcodegen generate выполнен.
- Общий roleToolCatalog: 4 PASS, 1 прежнее падение ожидаемого кода FORBIDDEN для secretary/plan_request; то же падение воспроизведено на исходной версии без изменений материалов. В эту работу не включено.
- UI-тесты, полную сборку приложения и установку на iPhone не выполняли. Живых тестовых сообщений и документов не создавали. Для открытия ссылок нужна установка версии iOS с этим изменением; существующая версия iPhone не умеет маршрутизировать note:// из этих элементов.

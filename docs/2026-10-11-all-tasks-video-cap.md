# 2026-10-11 — «Все задачи» в меню «…» и порог видео-портретов

Владелец: Максим. Строка реестра: `LOCK-ALL-TASKS-VIDEO-CAP-20261011`.

Задача пришла следом за снятием верхней полосы статусов из «Проектов»
(`docs/2026-10-11-projects-tiles-status.md`): вместе с плитками ушёл вход в
общий список задач, а раздел «Без проекта» показывает только задачи вне
проектов — не то же самое.

## 1. «Все задачи» — куда положил

Пункт в меню «…» раздела «Проекты», под «Поиск проектов».

| Файл | Что |
| --- | --- |
| `AppRoute.swift` | новый маршрут `allTasks` |
| `RouteDestinationView.swift` | его destination: `ProjectTasksScreen(projectID: nil, showsAllProjects: true)` |
| `ProjectTasksScreen.swift` | режим `showsAllProjects`, снятие проверки проекта в отборе, заголовок и пустое состояние |
| `ProjectsScreen.swift` | пункт «Все задачи» |

Отдельный экран не заводил: это ровно тот же список задач, только без сужения до
одного проекта. В `ProjectTasksScreen` добавлен параметр `showsAllProjects`
(по умолчанию `false` — поведение проектов, «Без проекта» и архива не меняется).
В отборе проверка проекта заменена на замыкание:

```swift
let inScope: (ApiTask) -> Bool = { showsAllProjects || $0.projectId == projectID }
```

Показываются корневые задачи всех проектов, с тем же фильтром по состоянию и
той же сортировкой «закреплённые сверху».

### Ограничение, о котором надо знать

Раздел «Связанные задачи» (дочерние) в этом режиме **не подгружается**. Он
строится отдельным запросом по каждому проекту, и на общем списке он только
раздувает его; корневые задачи показывают тот же состав работы. Если нужен
полный разворот по всем проектам — это отдельная работа с запросами.

## 2. Порог видео-портретов

**Порог — 5 одновременных видео-кружков на экране.**

### Что происходит

Каждый кружок портрета роли — отдельный `AVQueuePlayer` с `AVPlayerLooper`
(`TFRolePortrait.swift`, комплект «Гравюра», LOCK `TEAM-AVATAR-ANIMATION`).
Они заводятся на `makeUIView` и живут, пока вью на экране. Теперь их число
ограничено: кто не влез в бюджет — рисуется **статичной картинкой**, она уже
и так есть в том же компоненте (`TFRolePortrait` выбирает `inner`).

Порядок выдачи: `onAppear` идёт сверху вниз, поэтому в лимите остаются кружки
ближе к началу списка. Прокрутил — ушедшие с экрана освобождают слоты (слот
снимается в `onDisappear`), пришедшие занимают.

### Почему именно 5

- 5 — примерно столько строк крупного списка помещается в первый экран. Дальше
  по списку всё равно не смотрят в упор, а разницы «живая/статичная» в восьми
  кружках 18pt глаз не выхватывает — только нагрузка растёт.
- Запас большой: каждый плеер тянет несколько потоков декодирования. Было 199
  потоков и 20 видеоконвертеров на 69 кружках — зависание. При 5 их будет
  втрое-вчетверо меньше, то есть тупика не будет даже на длинном списке.
- Порог единый для приложения, а не подбирается под каждый экран: кружки
  считаются в общей очереди, место занимает тот, кто выше.

Отдельную галочку «Анимировать» в «Внешнем виде» не трогаю — порог работает
поверх неё. Выключил анимацию — все кружки статичны, как раньше.

### Где

Одно место: `Sources/DesignSystem/Components/TFRolePortrait.swift`.
Появился `TFPortraitVideoBudget` — `@MainActor`-объект с `@Published`-множеством
занимающих слот и `static let limit = 5`. Пять мест отрисовки портрета роли
(`TFAvatar`, `TFTeamAvatarStack`, `RoleAvatarView`, `AgentWorkAvatarView`,
превью в «Внешнем виде») идут через `TFRolePortrait`, поэтому ограничение
покрывает их все без правок в каждом.

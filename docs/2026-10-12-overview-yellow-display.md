# Заголовки разделов «Обзора» жёлтым капсом

LOCK: `LOCK-OVERVIEW-YELLOW-DISPLAY-20261012`

## Работа

Владелец дал образец (кадр «ЗАВОД №7»): узкий жирный дисплейный капс жёлтым,
все заглавные, без иконок и без пояснений. Попросил использовать на iPhone в
приложении, конкретно — разделы экрана «Обзор». Остальные цвета не трогать.
Гарнитуру назвал: **Big Shoulders Display**.

## Результат

Заголовки строк навигации набраны узким жирным капсом, без иконок и без
подзаголовков-пояснений. Цвет — **проектный** (`Color.tfText`), не жёлтый из
макета.

Две правки, которые я сделал по своей воле и владелец убрал:

1. **Жёлтый из образца.** Просили цвета сохранить — я перенёс жёлтый из чужого
   макета в приложение. Убрано, цвет снова `Color.tfText`.
2. **Подпись секции «НАВИГАЦИЯ».** Её в приложении никогда не было, я её
   придумал. Убрано.

## Ключевое решение: почему не Big Shoulders Display

**У Big Shoulders Display нет кириллицы.** Заголовки разделов русские, этой
гарнитурой они бы не набрались — только пустые прямоугольники.

Проверено напрямую по таблице `cmap` самого файла, а не по описанию:

- Google Fonts, `ofl/bigshouldersdisplay/BigShouldersDisplay[wght].ttf`
  → нет ни U+0410 «А», ни U+044F «я» (есть латиница, `№`, `—`);
- оригинальный репозиторий `xotypeco/big_shoulders`, ветка `master`
  (владелец дал ссылку именно на него) — проверены все три начертания
  `BigShouldersDisplay-{Black,ExtraBold,Bold}.otf` → кириллицы нет в каждом.

Взята **Oswald Bold** — ближайшая узкая жирная гротеск-гарнитура с полной
кириллицей, тот же характер. Если у владельца найдётся версия Big Shoulders
Display с кириллицей, подмена — это замена двух файлов в `Resources/Fonts` и
одного имени в `TFSectionDisplayModifier`.

## Что сделано

| Файл | Что |
|---|---|
| `Resources/Fonts/Oswald-Bold.ttf`, `Oswald-SemiBold.ttf` | Статичные начертания (700/600), кириллица + латиница, 89 КБ каждый |
| `project.yml` | Каталог `Resources/Fonts` в `sources` с `buildPhase: resources`; ключ `UIAppFonts` |
| `Sources/DesignSystem/Theme/Typography.swift` | `TFSectionDisplayModifier` + `.tfSectionDisplay(style:color:)`; константы трекинга в `TFFont` |
| `Sources/Features/Directory/OverviewScreen.swift` | Заголовок секции «НАВИГАЦИЯ», строки без иконок и пояснений, инсет разделителя пересчитан |

Файлы шрифта статичные, вес зафиксирован инстанцированием оси `wght`
(fontTools): переменный `Oswald[wght].ttf` в приложение не класть — iOS не
обязан уметь вариативные оси, а здесь нужна предсказуемость начертания.

## Проверки

1. **Сборка** `xcodebuild … -destination 'iPhone Air,OS=27.0'` — BUILD SUCCEEDED.
2. **Шрифт в бандле** — `ls TaskFlow.app` показал оба `Oswald-*.ttf`.
3. **UIAppFonts в собранном приложении** — `plutil -p TaskFlow.app/Info.plist`
   вернул оба имени.
4. **Кадр симулятора** `docs/2026-10-12-overview-yellow-display/simulator-overview.png` —
   узкий жирный капс, кириллица на месте, жёлтый, иконок и пояснений нет.

## Грабли, на которые ушло время (полезно на будущее)

Обе причины молчаливые — ошибок сборки нет, кадр просто выглядит «не тем»:

1. **Ручная правка `Resources/Info.plist` пропадает.** xcodegen перегенерирует
   файл из `properties` в `project.yml` при каждой сборке. Правка `UIAppFonts`
   в самом plist была затёрта, шрифт лежал в бандле, но iOS его не
   регистрировал. Ключ обязательно задавать в `project.yml`.

2. **`Font.custom("Oswald Bold")` молча рисует системным шрифтом.** В файле
   family = «Oswald» (name ID 1), а «Bold» — начертание (name ID 2).
   Правильно: `Font.custom("Oswald")`. Ошибки нет, `.weight()` ничего не
   сообщает — видно только на кадре.

## Границы

- Изменён только экран «Обзор». Другие экраны не тронуты.
- Общий компонент `TFListRow` не переделывался под «без иконок» — на
  «Обзоре» используется своя строка, чтобы не ломать 100+ мест.
- iPhone не проверялся: собирал и снимал на симуляторе iPhone Air iOS 27.0.

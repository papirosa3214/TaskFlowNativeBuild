## Причины и изменения
- Native row считал running только по derived state, хотя preview считал также agent_state=in_progress. Теперь одинаковая проверка: незакрытый шаг и одно из двух состояний работы.
- loadActivity не вызывал сервер при отсутствии in_progress в снимке родительской карточки. Решение об актуальности аренды остаётся серверу, клиент запрашивает канал, пока карточка открыта.
- ApiTaskActivity.isActive учитывает действия даже до готовности текстового пересказа.
- Для blocked/review восстановлено использование существующего TFSubtaskStatusRing. Крутилка остаётся под задачей.
- Участник общего графа открывает сразу PlanStepDetailSheet: выбирается активное, затем заблокированное/возвращённое/проверяемое, затем незавершённое поручение. Другие поручения той же роли доступны в выборе внутри полного листа.
- Подробности общего графа получают результат из исходной карточки/source plan/source slot, а не ищут дочерний шаг среди root subtasks.
- Работа на графе обозначается отдельным молоточком; Reduce Motion отключает движение. Размеры и маршруты графа не менялись.
- Сервер inProcessRun отправлял bash kind=bash, который API активности не принимает. Маппинг теперь bash→run, grep/find→search, write→write. Другие механизмы выполнения не менялись.

# Ответы ролей в карточке: общий JSON-рендер

26.10.2026. Прямое поручение владельца: быстро и минимумом шагов.

В TaskFormScreen комментарий выводился простым Text, а результаты шагов шли в Markdown-парсер без распознавания raw role.v1 envelope. Подключён TaskRoleReply: существующий ChatStructuredOutputView для JSON; существующий RoleReplyMarkdown для старой размётки ролей; простой Text для остальных сообщений. Глобальный RoleReplyMarkdown.readableText и шрифты не менялись.

TaskRoleContent распознаёт канонический schema_version=1, а также старые «Ревьюер вернул на доработку: [дефекты]» и «changes_requested: [дефекты]»: преобразует их в тот же v1 envelope с heading/text блоками. Машинные поля и workflow-префиксы на сервере не изменяются. Разбор кэшируется, включая отрицательный результат; обычные записи журнала не проходят полный rich-парсер. Роль определяется по accountID из реестра ролей и совместимым штатным ID, пользовательский текст не конвертируется.

Проверки: 3 XCTest на macOS PASS; RED без преобразователя (nil baseline) → GREEN на настоящем TaskRoleContent. Кейсы: JSON напрямую/в tf-json fence, фактическая форма замечаний критика с location/priority, machine prefix, обычный текст, повреждённый JSON, пустой массив. xcodegen generate, Swift parse, design-system-guard и diff --check PASS. Симулятор, UI-тесты, сборка и iPhone не запускались.

Серверная нормализация/валидация комментариев и результатов передана существующему разработчику в карточке e11eae7a-2198-41af-9244-de7a82164882, сообщение 1d52fa25-1ef5-445d-9078-8bba621487ae. На момент сдачи этой клиентской правки серверный результат не подтверждён. Это совместимость чтения и рендер, не гарантия, что все будущие сообщения уже приходят правильным JSON.

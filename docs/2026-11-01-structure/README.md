# Milestone 2 «Разбивка по смыслу» — доказательство, что переезды ничего не изменили

Дата: 01.11.2026. Фича миссии `m2-verify-after-moves`.
Утверждения контракта: VAL-STRUCT-013, VAL-STRUCT-014, VAL-STRUCT-015, VAL-STRUCT-016.

## Итог одной строкой

Четыре статических сторожа зелёные, проект собирается, пять затронутых экранов
запускаются на разрешённом симуляторе, и после исключения двух системных областей
(часы iOS и анимированные портреты ролей) **картинка базы и картинка после
переездов совпадает пиксель в пиксель — ноль отличающихся пикселей на всех пяти
экранах**.

## Что сравнивали

| | база | после переездов |
|---|---|---|
| ревизия | `$(git merge-base HEAD origin/main)` = `2222885d` | `HEAD` = `8b928937` |
| worktree | `/tmp/tf-base` (отдельный, `git worktree add`) | текущий |
| сборка | `xcodegen generate` + `xcodebuild … generic/platform=iOS Simulator` → **BUILD SUCCEEDED** | то же → **BUILD SUCCEEDED** |
| установка | `xcrun simctl install 9FF78D89-EE84-4914-AA56-D0A72D1AF43A …` | то же |
| данные | офлайн-фикстура `127.0.0.1:3307` (`Tools/websocket-energy-fixture.py`) | **тот же самый процесс фикстуры** |

База взята через `merge-base`, а не жёстким SHA: после rebase фиксированный SHA
перестаёт быть предыдущим состоянием, и в сравнение попали бы чужие изменения
upstream. Фикстура — **один и тот же долгоживущий процесс** на обе ревизии,
поэтому данные в кадрах идентичны по построению. Сравнение против живого сервера
`192.168.1.110:3001` доказательством «ничего не изменилось» не было бы: там данные
меняются между двумя прогонами.

Симулятор — только разрешённый: iPhone Air, iOS 27.0,
UDID `9FF78D89-EE84-4914-AA56-D0A72D1AF43A`.

## Четыре статических сторожа (VAL-STRUCT-013)

Лог: `.worktrees/_bg/struct-013.log`.

| сторож | результат | код |
|---|---|---|
| `python3 Tools/design-system-guard.py --folder` | `Сторож дизайн-системы: чисто.` | 0 |
| `bash Tools/ui-drift-scan.sh` | `Новых отклонений (NEW): 0` (KNOWN 23 — те же, что и до переездов) | 0 |
| сторож цвета (через API модуля) | `color_total=228 color_enabled=0` | 0 |
| сторож заголовков (через API модуля) | `heading=0` | 0 |

**Сторожи цвета и заголовков запускались не как скрипты.** `Tools/control-color-guard.py`
и `Tools/screen-heading-guard.py` — библиотечные модули без `__main__`: прямой запуск
выходит с кодом 0 и пустым stdout независимо от содержимого кода, то есть «0 нарушений»
неотличимо от «сторож вообще не запустился». Проверка шла через API модуля
(`scan_control_colors`, `scan_screen_headings`) — тем же путём, что и
`Tools/design-system-guard.py`: `contract-work/_guards.py color` / `headings`.

233 → 228 находок по цвету — расхождение с замером 31.10.2026 (233) объясняется тем,
что часть находок приходится на файлы, уехавшие в `DesignSystem/` и выпавшие из
проверок `red-button`/`implicit-system-blue` (`Tools/control-color-guard.py:169`).
По **включённым** правилам — ноль. Выключенные владельцем правила (`red-button` 45,
`implicit-system-blue` 183) считаются, но не считаются провалом.

Хостовые тесты `Tools/test_*.py` — 51/51 PASS.

Лог: `.worktrees/_bg/struct-014-build.log`. Собираются **обе** ревизии
(base → `** BUILD SUCCEEDED **`, HEAD → `** BUILD SUCCEEDED **`).

`git diff origin/main..HEAD -- project.yml` — одна строка, и она в комментарии:

```diff
-      # `AgentAvatarView` в `Sources/Features/Chat/AgentRow.swift`.
+      # `RoleAvatarView` в `Sources/DesignSystem/Components/RoleAvatarView.swift`.
```

Блок `sources:` не тронут: в нём по-прежнему `- path: Sources`, который xcodegen

не появилось.

### Экран «ЧАТЫ»: почему полное сравнение не годится

Различия на «ЧАТЫ» — **анимированные портреты ролей** на выезжающей панели справа
(`AnimatedImage` из SDWebImage, `Sources/DesignSystem/Components/TFAvatar.swift:177`).
Это не данные и не следствие переезда: тот же экран **той же сборки**, снятый дважды
подряд с интервалом 2 секунды, отличается на **5,5 %** (189 637 пикселей) — карта
различий `diff/diff-chat-ctrl.png` показывает: девять из одиннадцати портретов
изменились целиком, но **остались на своих местах и того же размера**.

| сравнение | ratio | габариты различий |
|---|---|---|
| base против after | 1,48 % | `x 155…1247`, `y 93…2285` |
| контроль: та же сборка, 2 с | 5,50 % | `x 1092…1247`, `y 402…2285` |

Разница между базой и после переездов **меньше собственного шума этого экрана**.
Пиксельный порог 1 % на «ЧАТЫ» недостижим в принципе: любые два кадра одной сборки
дают больше 1 %.

### Геометрия панели портретов совпадает

Портрет занимает круг целиком, поэтому профиль «тёмных пикселей по строкам» полосы
не зависит от того, какой кадр анимации попал в снимок, но зависит от числа,
размера и положения портретов (`.worktrees/_bg/stripprofile.swift`):

| сравнение | строк с отличием | макс. разница в строке |
|---|---|---|
| base против after | 296 / 2736 | 8 px |
| контроль (2 с) | 1 359 / 2736 | 57 px |

Один и тот же набор портретов, на тех же местах, того же размера. Разница между
базой и после переездов в 4,6 раза ближе к нулю, чем шум той же сборки.

### Сравнение с исключёнными системными областями

Исключаются ровно две области, обе — не содержимое приложения:

## Что попутно починили в офлайн-фикстуре

`Tools/websocket-energy-fixture.py` на неизвестный путь отдавал `{}`. Модель
`ApiAttention` требует `ok` и `groups`, поэтому декодер `/api/attention` падал, и
экран «Входящие» показывал баннер «Не удалось разобрать ответ сервера: The data
couldn't be read because it is missing» вместо данных. Это был пробел фикстуры, а не
поломка приложения (та же история с `/api/stats/review-history`, закрытая фичей
`m2-path-artifact-hygiene`).

Фикстура теперь отдаёт для `/api/attention` одно обращение, привязанное к задаче
фикстуры (`task_id: "energy"`), — на экране «Входящие» появился настоящий
интерактивный элемент (карточка со ссылкой на задачу) вместо баннера ошибки.
Без этого доказательство «те же данные и те же интерактивные элементы» было бы
пустым: сравнивать баннер ошибки с баннером ошибки — это не проверка.

Правка в `Tools/` — вне `Sources/`, поэтому на VAL-STRUCT-006 не влияет
(`_struct006.py` сканирует только `Sources/`).

## Ограничения

- **Внешний вид не принимался.** По правилу миссии визуальную приёмку объявляет
  владелец. Здесь доказано другое: переезд не изменил картинку.
- **Тёмная тема не снималась** — сравнение шло в светлой теме, какой отдаёт
  симулятор по умолчанию.
- **Планировщик не сравнивался** — у него нет отладочного маршрута (см. VAL-ROUTE-002).
- Сравнение шло против офлайн-фикстуры, а не против живого сервера: так обе ревизии
  гарантированно видят одни и те же данные.

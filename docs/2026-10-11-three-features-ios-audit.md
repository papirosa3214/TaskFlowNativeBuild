## Вебхуки V2 — воспроизведённые дефекты

Источники: `Sources/Features/Settings/WebhooksAPI.swift`, `WebhooksScreen.swift`; серверный контракт `server/src/lib/webhookSubscriptions.ts` на опубликованной в Gitea интеграционной ветке f97a1824.

1. `WebhookTestResult` требует верхнеуровневый `wake_confirmed: Bool`. V2 возвращает `delivered`, `http_status`, вложенный `wake.{queued,codex_followup_id,acked,acked_at,error}`. JSONDecoder падает keyNotFound("wake_confirmed"). Кнопка «Проверить доставку» на изолированном V2 fixture показала «Не удалось разобрать ответ сервера: The data couldn’t be read because it is missing.».
2. Список подписок V2 сообщает подтверждение в `last_wake_ack.{acked,acked_at,kind}`. iOS читает старое `wake_confirmed_at` и при fixture acked=true всё равно пишет «Запуск оркестратора не подтверждён».
3. Сервер возвращает `last_wake_at` и `last_wake_error` на верхнем уровне. iOS ищет их внутри `wake`; время очереди и ошибки могут пропадать.
4. Форма добавления содержит прежний default thread ID `01a120f9-1266-7331-a4ca-81f6da2a698b`, а карточка доработки называет новый чат `01a123bf-a2c4-7192-914b-40ad28bbf3c5`. Автоматической актуализации назначения в коде нет; существующие настройки владельца аудит не менял.

Живой GET списка подписок вернул 200 и пустой список. Воспроизведение V2 выполнено на localhost fixture 3327, без создания живых подписок, без настоящего wake и без расхода на запуск модели.

## Гант — живой API и данные

GET `http://192.168.1.110:3001/api/coordination/role-load?window=24h` с заголовком ios-native на момент проверки: HTTP 200, roles=9, attempts=230, active_now=0, open_slots=10. Это свежее состояние: старый отчёт 10.10 фиксировал 404.

XCUITest открыл «Обзор» → «Загрузка ролей», дождался chart, выбрал «Неделя» и дождался значения week. Кадры сутки/неделя сняты с живого API. Но все 230 attempts из контрольного ответа имеют routing_role=null. Модель `RoleLoad.rows` группирует их по пустому ключу и честно рисует «Без роли», поэтому именованные дорожки пусты. Это препятствует подтверждению цели «загрузка ролей по факту», несмотря на успешную загрузку и навигацию. Переход в карточку задачи в этом прогоне не повторялся; старый fixture-отчёт подтверждает его отдельно.

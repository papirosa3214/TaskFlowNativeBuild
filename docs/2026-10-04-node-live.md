# Исполнитель слота и живые действия — 04.10.2026

Личная работа использует исполнителя карточки, командная — исполнителя активного рабочего слота. Ручное назначение владельцем не требуется.

## Диагностика
MAK-42: assignee карточки пустой, активный слот role_builder. Авторизация activity через карточку возвращала 404; runtime продлевал heartbeat карточки вместо слота. Старый результат блокировки показывался вместе с новым запуском.

## Изменения
Сервер предоставляет telemetry исполнителю его активного незавершённого слота; heartbeat runtime направляется в subtask/work. Продлевается также попытка. Изменение не назначает исполнителя карточки.

В деталях узла: роль и состояние вместе, состояние «В работе» раскрывает текущие действия; единое задание, ожидаемый результат, отдельная история предыдущего результата. Просроченный слот не показывает работающую крутилку.

## Проверка
21 целевой серверный тест пройден, TypeScript без ошибок. XCUITest воспроизвёл отсутствие раскрытия до правки, после правки прошёл с проверкой текста действий. Скриншот: [live.png](2026-10-04-node-live/live.png).

Сборка для устройства прошла; IPA подготовлена в `build_device/TaskFlow.ipa`. На физическом iPhone эта версия ещё не проверена.

## Установка
Серверное исправление установлено на .110 и сервер перезапущен с разрешения владельца после подтверждения blocked/released. Состояние разработчика осталось blocked, база integrity_check: ok. Симулятор использует fixture; живое восстановление MAK-42 пока не подтверждено.

## Доработка карточки слота
Задание, ожидаемый результат и зависимости объединены в одну группу с разделителями. Пустые поля и повторяющийся текст не создают лишних строк. Роль и раскрываемое состояние в первой группе, прежний результат отдельно от текущих действий. XCUITest NodeLiveUITests PASS, device BUILD PASS. Скриншот live.png обновлён; changes.diff фиксирует накопленные изменения по отслеживаемым файлам. Новая TaskLiveActivityView.swift сохранена отдельным исходником. Физический iPhone пока не проверен.

## Копирование результата
Кнопка doc.on.doc в начале результата копирует полный исходный текст в системный буфер; подтверждение checkmark. Результат, задание и текущая фраза поддерживают textSelection. До правки тест отсутствующей кнопки FAIL, после — нажатие и подтверждение PASS; device BUILD PASS. Скриншот copy.png. Новый отчёт MAK-42 сообщает о gate claim/subtask_work, а не об отсутствии mac_write_file; этот отдельный серверный блокер в данной правке не менялся.

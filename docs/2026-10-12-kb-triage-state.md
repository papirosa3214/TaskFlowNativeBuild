# «Разбор заметок» в «Состоянии системы»

12.10.2026 · LOCK-KB-TRIAGE-STATE · opencode

## Поручение

> «Ты посмотри в обзоре, есть раздел состояния системы, и вот там, туда
> вообще идёт обработка, в этот раздел вот таких вот вещей, которые сейчас
> вот ты найдёшь автоматику. Ты вот посмотри по образцу, как организовано
> состояние системы с такими вот автоматами. И точно так же организуй вот
> это вот.»

Началось с вопроса владельца: «А кто создал вот эти вот „разобрать
накопившиеся заметки“?»

## Что нашлось при разборе

Задачи «Разобрать накопившиеся заметки: N ждут разбора» заводит не человек:
это сторож порога базы знаний — `server/src/lib/kbTriageWatcher.ts` на `.110`.
Он считает заметки с временной меткой и без постоянной категории; набралось
больше порога (20) — заводит задачу роли «Секретарь» в проект
`TaskFlow - NewTodoist`, от имени владельца (`creator_id = u1`).

**Дефект, который вскрылся:** за час (18:25–19:23) появилось **семь
одинаковых карточек**. Причина — суточный интервал «не чаще раза в сутки»
держался в переменной в памяти процесса:

```ts
let lastRaisedAt = 0
if (now - lastRaisedAt < DAY_MS) return
```

Перезапуск сервера обнулял переменную, и сторож заводил задачу заново.
Семь задач = семь перезапусков.

## Что сделано

### Сервер (`New-Todoist` на `.110`, коммит `cab0e53a`)

Отметка переехала на диск — по образцу планировщика
(`~/.local/state/taskflow-scheduler/last-run.json`):

- `~/.local/state/taskflow-kb-triage/state.json`: `checked_at_epoch`, `pending`
  (пишутся при каждой проверке, до порога), `raised_at_epoch`,
  `raised_task_id` (при заведении задачи);
- при старте суточный интервал восстанавливается с диска — **дубли при
  перезапуске больше не появятся**;
- новая `kbTriageState()` отдаёт состояние для экрана;
- `GET /api/agent-service` возвращает его полем `kb_triage` рядом с
  `scheduler`.

Сборка `npm run build` (сервер работает из `dist`, не из исходников —
перезапуска без пересборки было бы недостаточно), `npx tsc --noEmit` чистый.

### Клиент (этот репозиторий)

- `KbTriageRunState` в `APIClient+SystemControl.swift` + поле `kbTriage`
  в `SystemRunState`. Все поля декодируются мягко: у сервера старой версии
  блока нет, и ронять из-за него тумблеры рядом нельзя.
- Строка **«Разбор заметок»** в `SystemControlSection` — тем же видом, что
  «Расписание» выше: лампа 7 pt слева от значения, значение справа.

Лампа:

| Цвет | Когда |
|---|---|
| серая | состояние не прочитано (сервер старой версии) |
| зелёная | сторож жив, разбирать пока нечего |
| оранжевая | накопилось до порога — задача заведена, но не разобрано |
| красная | сторож молчит дольше двух проверок |

Значение справа — «N из M»: сколько заметок ждёт разбора против порога.
Строки нет вовсе, если сервер поля не отдал.

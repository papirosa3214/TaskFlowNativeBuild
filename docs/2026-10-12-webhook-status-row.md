# Индикация вебхуков в настройках — 12.10.2026 (не актуально)

## Работа

Поручение владельца: фоновый сторож, который проверял wake-канал вебхуков, не
нужен; вместо него в приложении должна быть индикация — работают вебхуки или
нет. Отдельно владелец перечислил ручки, которые уже есть: перезапуск сервера,
пинг, задачи, адрес сервера. Уточнили: индикация — в секцию «Сервер» на главном
экране Настроек, а пинг/перезапуск/задачи не трогать (они там уже есть, дубли
расходились бы в показаниях — та же история, что с «Будильником»).

## Результат

В секции «Сервер» настроек появилась строка «Вебхуки», которая отвечает на
вопрос «работают или нет» без фоновой проверки на сервере.

## Что сделано

- `Sources/Features/Settings/WebhooksAPI.swift`: в модель `TaskFlowWebhook`
  добавлены `deliveryCount`, `wakeCount`, `lastDeliveryStatus`. Поля
  опциональные — старый сервер без них не ломает разбор ответа.
- `Sources/Features/Settings/ServerStatusSection.swift`:
  - вью-модель грузит `/integrations/webhooks` третьим параллельным запросом к
    `/server-status` и `/agent-service` — экран не стал медленнее;
  - `WebhookState` перечисляет исходы: `unknown` (раздел не отдан сервером),
    `none` (подписок нет), `disabled` (выключены), `broken(причина)` (ошибка
    доставки), `works(число доставок)`;
  - строка «Вебхуки» в `loadedRows`, тап — перечитать факт, без побочных
    эффектов;
  - цвета те же штатные, что у остальных показаний: `tfGreen` — работает,
    `tfCoral` — сломано, `tfSub` — серый. Новых цветов не заводим.

Серверные правки для этого НЕ потребовались: `GET /api/integrations/webhooks`
уже отдаёт `enabled`, `delivery_count`, `last_delivery_status`, `last_error`.

## Проверки

- `BUILD SUCCEEDED` (iPhone Air, iOS 27).
- Временный XCUITest `TempServerSectionWebhooksUITests`
  `testСекцияСерверСоСтрокойВебхуков` — passed: открыл настройки маршрутом,
  довёл строку до середины экрана, снял кадр. Тест удалён после сверки.
- Кадр: секция «Сервер» — строка «Вебхуки» с показанием «нет подписок».
- Показание сверено с фактом: `SELECT … FROM webhook_subscriptions` на сервере
  возвращает ноль строк, то есть «нет подписок» — правда, а не ошибка чтения.

## Ограничения

- Сейчас подписок нет ни одной, поэтому зелёный путь «работают · N» на живых
  данных не проверен — только ветки «нет подписок». Логика вывода покрывает
  ошибку (`last_error` либо HTTP ≥ 400) и выключение.
- Тап по строке только перечитывает данные. Пробная доставка (реальный запрос
  к приёмнику) осталась на экране «Вебхуки» в интеграциях — вызывать её из
  показания без явного намерения владельца было бы самодеятельностью.

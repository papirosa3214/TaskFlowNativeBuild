# В чате с ролью — «мозг» и папка — 29.10.2026

## Задача

Владелец, 29.10.2026 (скриншот чата): «тут интерфейс забаговался вместо того,
чтобы был мозг, где можно выбирать модели с уровнем рассуждений и папка, где
можно выбирать рабочую папку проекта… Четыре кольца контекста отображается.
Просто в чате с помощником там немножечко другая схема. Ну а с другими всеми
ролями должна быть именно та схема, которую я озвучил. Там мозг и папка».

## Что было не так

Схема ряда ярлычков в композере (`ChatVoiceComposer.promptComposer`):

```swift
if let sessionControls { sessionControls }          // чат с Помощником: кнопка «Сессия»
else {
    мозг (модель) + папка (рабочая папка) + кольца контекста
}
```

Два ограничения закрывали «мозг» и папку в личных чатах с ролями:

1. **Мозг** (`ChatModelChoice.load`): `guard roles.count == 1` — роль бралась из
   `chat.members.compactMap(\.roleKey)`. В комнате ролей их несколько, и выбор
   модели там не к кому было привязывать. В личном чате с ролью мозг был.
2. **Папка** (`ChatWorkspaceChoice.load`): `guard chat.members.contains(where:
   { $0.id == "u-secretary" || $0.roleKey == "secretary" })` — только чат с
   Помощником. В личном чате с любой другой ролью папки не было вовсе.

А уровня рассуждений в «мозге» не было вообще нигде, кроме панели сессии
Помощника: в меню модели (`ChatModelMenu`) есть только список моделей, а
`ChatModelChoice.save` для не-помощниковских чатов писал выбор в `UserDefaults`
и обнулял `thinkingLevel`.

Сервер отдавал рабочую папку для любого чата (`GET /api/chats/:id/workspace`
проверяет только, что чат есть и запросил владелец), а вот предпочтения хода
(`/api/chats/:id/session-preferences`) пускал только в чат с Помощником —
`!members.some(m => m.member_id === "u-secretary")` → 400.

Итог: в личном чате с ролью (кроме Помощника) ряда ярлычков не было вовсе — ни
мозга, ни папки; в комнате ролей были только кольца контекста.

## Что сделано

### Сервер (`papirosa3214/New-Todoist`, PR #26)

`server/src/routes/chat-session-preferences.ts` — предпочтения хода доступны в
любом личном чате с одной ролью:

- роль определяется по второму участнику (`role_<ключ>` или `u-secretary`),
  а не жёстким «Помощник»;
- модель по умолчанию берётся из маршрутизации этой роли
  (`loadRoleRouting().models[roleKey]`), у Помощника — как и раньше;
- комната с несколькими ролями — по-прежнему без настроек хода (там своя
  схема: кольца контекста).

### iOS-клиент

- `ChatModelChoice.load` — роль чата берётся из `chat.composerRoleKeys` (учитывает и `u-secretary`, и `role_*`); выбор и уровень размышлений хранит сервер, если он их отдал; иначе — прежний выбор на устройстве, без уровня размышлений.
- `ChatModelMenu` — в «мозге» появился раздел «Размышления» с уровнями выбранной модели (раньше он жил только в панели сессии Помощника).
- `ChatWorkspaceChoice.load` — рабочая папка в личном чате с любой ролью, а не только с Помощником.
- `RoleChatsScreen` — кольца контекста показываются в комнате ролей (ролей больше одной); в личном чате ряд ярлычков — это «мозг» и папка.

## Схема по чатам

| Чат | Ряд ярлычков |
|---|---|
| Личный чат с ролью | **мозг** (модель + уровень размышлений) + **папка** |
| Чат с Помощником | кнопка «Сессия» (там же модель, размышления и папка) |
| Комната с несколькими ролями | кольца контекста (по одному на роль) |

## Не доведено: PR New-Todoist #26 ждёт зелёного гейта

Серверный PR (#26) не сливается: тестовый гейт красный. Проверено, что падения
не от этой правки:

- локально те же файлы падают и с правкой, и без неё (подмена файла на базовый
  даёт тот же результат);
- в CI прогнан черновик-PR #27 на ЧИСТОЙ базе (пустой коммит поверх
  `main`) — он падает в тех же шардах 2/4 и 3/4. Черновик и ветка удалены.

Падения в чужих областях: запуск ролей (`roleProcessLifecycle`,
`localRoleOperations`, `runtimeAuditStart`), сообщения между ролями
(`agentMessaging`), живой ход (`chatLiveDelta` — тест ждёт полный снимок на
каждом flush, а в `main` снимок теперь раз в 10 с), `stepOutcome`,
`taskExecutionState`, `roleResultReport`. Часть падений — окружения GitHub-раннера
(`setfacl` на `/tmp` не проходит → роль не читает файлы → нет
`role-routing.yaml`), часть — рассинхрон теста с новой частотой снимков.

До зелёного гейта клиент работает с прежним сервером: мозг и папка на месте,
раздел «Размышления» не показывается (сервер не отдаёт предпочтения хода для
этого чата, клиент это переживает — выбор остаётся локальным).

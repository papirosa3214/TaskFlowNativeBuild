# Лента чата на нативной виртуализации — 10.11.2026

## Результат

Лента личной комнаты роли больше не `ScrollView` с обычным `VStack`. Строки
живут в `UITableView` (`ChatFeedVirtualList`): создаются только для видимого
участка, переиспользуются, высоту меряет система по содержимому строки.
Правила «где лента и когда она идёт за низом» вынесены в чистую
`ChatFeedScrollPolicy` и проверяются тестом на хосте, без телефона.

Поручение владельца 10.11.2026: «давай все же сделаем уже по полной… мне по
большому счету вид нужен и визуал отображения всяких ссылок, так же поведение
ленты прям нравится ноль тупняка в отличии от моего чата».

## Что было и почему это дорого

Лента рисовалась так (`RoleChatRoomScreen.swift`, до правки :1336):

```swift
ScrollView {
    VStack(alignment: .leading, spacing: TFSpacing.md) {   // обычный, не ленивый
        ForEach(orderedFeed) { item in … }
    }
}
```

Окно — 10 последних сообщений, но каждое длинное: 22–27 тыс. pt на всё окно.
`VStack` монтирует все строки сразу, вместе со всеми сегментами ответов
(`ChatReplyMarkdown`, таблицы, виджеты, код), и держит их живыми. Ленивый
вариант пробовали 07.11 и откатили: `LazyVStack` угадывал высоту невидимых
строк, якорь низа перескакивал, лента уезжала вверх и шаталась
(`docs/2026-11-08-chat-feed-load-more.md`).

## Как у T3 Code (по исходникам, `pingdotgg/t3code`, MIT)

Мобильная лента — `KeyboardAwareLegendList` с `estimatedItemSize: 180`,
`drawDistance: 500`, `maintainVisibleContentPosition`, `maintainScrollAtEnd`,
`alignItemsAtEnd`, `initialScrollAtEnd` и `getItemType` (свой пул
переиспользования на каждый тип строки). Markdown рисует нативный текстовый
модуль, а не дерево вью. То есть выигрыш там не в «магии», а в виртуализации:
живёт только видимое, высота измеренная, строки переиспользуются.

## Что сделано

1. `Sources/Chat/Feed/ChatFeedVirtualList.swift` — лента на `UITableView`:
   - `automaticDimension` + `estimatedRowHeight`: высота строки измеряется по
     содержимому, а не угадывается;
   - ячейка — `ChatFeedHostingCell` с `UIHostingConfiguration`, содержимое —
     прежняя SwiftUI-строка (вид не менялся);
   - содержимое строки — `ChatFeedVirtualRow(id:version:)`: пересобирается
     только строка, у которой сменилась версия (событие по этому сообщению,
     режим выбора), остальные не трогаются;
   - удержание низа: пока лента идёт за низом, рост содержимого (печатается
     ответ, поднялась клавиатура) доводит смещение к низу; отпускает низ
     только рука владельца;
   - старые сообщения, добавленные при дорисовке, не прыгают: смещение
     компенсируется на высоту появившегося сверху;
   - `bottomEdgeEffect.style = .soft` на iOS 26 — то же затухание у нижней
     кромки, что было у `ScrollView`.
2. `Sources/Chat/Feed/ChatFeedScrollPolicy.swift` — чистая геометрия: `nearBottom`
   (80 pt), `nearTop` (300 pt), «меняется ли привязка к низу», смещение у низа.
3. `Sources/Features/Roles/RoleChatRoomScreen.swift`:
   - `messageScroll` собирает строки и отдаёт их ленте; сюда же переехали
     приветствие роли/пустое состояние, голосовые «в пути» и строка «печатает»;
   - кнопка «вниз», отправка сообщения и переход по оглавлению зовут команды
     ленты (`ChatFeedScrollHandle`) — экран больше не ведёт смещение сам;
   - убраны ставшие ненужными состояния и модификаторы прокрутки
     (`chatScrollPosition`, `chatFollowsBottom`, `chatScrollPhase`,
     диагностическая `ChatScrollTrace` с логом геометрии), которые спорили
     за offset между собой (владельцы 30.10 и 07.11.2026).
4. `Tests/ChatFeedScrollPolicyTests.swift` + `Tools/test_chat_feed_scroll_policy.py` —
   целевой тест правил прокрутки на хосте.

## Ограничения (честно)

- **Визуально не проверено.** Внешний вид ленты, отступы между строками и
  поведение прокрутки оценивает владелец. Сборка и тесты логики этого не
  доказывают.
- **Клавиатура и поле ввода** вживую не проверялись: удержание низа при
  подъёме клавиатуры реализовано в `layoutSubviews` таблицы, но проверено
  только сборкой.
- **Дорисовка старых сообщений** проверена логикой (`RoleChatFeedWindow` +
  компенсация смещения), но не жестом на телефоне.
- Строки с асинхронно подгружаемым содержимым (изображения, длинный код)
  меняют высоту после загрузки — таблица пересчитывает её сама, но на живом
  чате это не проверено.
- Спецэффект затухания у нижней кромки работает только на iOS 26.

## Правка 10.11.2026 после установки: рамка, кромки, горизонтальная прокрутка

Владелец, посмотрев на телефоне: «чат как будто в своем окне… по краям нет
отступов, зато сплошняком идёт низ и верх экрана без режима затухания эпл, и
появилась горизонтальная прокрутка».

Что исправлено (`ChatFeedVirtualList.swift`):

1. **Горизонтальная прокрутка** — строка с широким содержимым (таблица, код)
   растягивала таблицу шире экрана. Теперь каждая строка собирается ровно по
   ширине ленты (`bounds.width − боковые отступы`), при смене ширины (поворот,
   появление панели) строки пересобираются; горизонтальный отскок выключен.
2. **Кромки и безопасная область** — `contentInsetAdjustmentBehavior` переведён
   с `.never` на `.automatic`: только так содержимое уходит под шапку и панель
   ввода и работает штатное затухание Apple. Мягкое затухание включено у обеих
   кромок (было только снизу).
3. **Отступы** — свои вертикальные уменьшены до `TFSpacing.sm` (верх и низ
   добирает безопасная область), боковые остались `TFSpacing.lg`.

Проверки: компиляция в отдельном рабочем дереве на HEAD — ошибок сборки нет
(падает только фаза сторожа дизайн-системы, у которой в рабочем дереве нет
baseline); сторож дизайн-системы в основном дереве — чисто. Сборка в основном
дереве и установка на телефон не выполнялись: в дереве шли чужие
незакоммиченные правки `RoleChatsScreen.swift` и `ChatRoomsPanel.swift`,
которые на тот момент не собирались.

## Ещё правка 10.11.2026: лента не двигается вбок

Владелец после второй установки: «всё равно ещё двигается влево и вправо» —
то есть оставался горизонтальный отскок (широкое содержимое строки и
диагональный жест). Теперь у ленты горизонтального движения нет совсем:
`isDirectionalLockEnabled = true`, и любое смещение по X в
`scrollViewDidScroll` возвращается в ноль.

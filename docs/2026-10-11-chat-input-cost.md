# Задержка ввода в чате

Повторное вычисление feedItems для каждой строки заново сортировало всю историю и создавало форматтеры дат на каждом сравнении. На 39 сообщениях отдельный воспроизводящий Swift-замер показал 786,58 мс против 10,1 мс после вычисления дат и сортировки один раз. Это замер алгоритма, не времени клавиатуры на телефоне.

Лента теперь вычисляется один раз за построение списка; даты — один раз на сообщение. Неизменившиеся Markdown-ответы пропускают повторный разбор через Equatable. Идентичность и прокрутка списка сохранены.

Проверка: тесты роли/голоса и XCUITest порядка двух ролей после завершения ответа. Физический ввод требует проверки владельцем после установки.

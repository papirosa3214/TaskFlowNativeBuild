# Chat composer controls implementation plan

Goal: закрепить текущую панель ввода как компонент; реальные провайдеры, контекст и команды.
Architecture: один ChatPromptPanel для утверждённой панели; ChatVoiceComposer управляет диктовкой. Provider-qualified models, /chats/:id/controls по согласованному контракту карточки e11eae7a-2198-41af-9244-de7a82164882. Сервер делает команда TaskFlow; никаких внешних субагентов.

Constraints: только canonical Mac, simulator/UI tests/device install не разрешены. Не менять общий RoleReplyMarkdown и ленту сообщений. Исследование помощницы — toolkit исследователя, сама в чате.

- [ ] RED: macOS unit для одинаковых моделей разных провайдеров, неизвестного контекста/лимита/compaction, slash поиска/вставки без потери аргументов, роли secretary и режимов.
- [ ] Foundation models + API; группировка моделей по провайдерам без угадывания.
- [ ] Выделить ChatPromptPanel, убрать переключатель старой панели, объединить вложения и режимы в меню с иконкой slider.horizontal.3. Исследование доступно secretary.
- [ ] Индикатор контекста с сырым счётчиком/лимитом и свежестью; команды из действительного API; выбор вставляет в черновик, не отправляет.
- [ ] GREEN macOS, hint unit, xcodegen для новых Sources, Swift parse/guard, документ и собственный коммит.
- [ ] Проверить результат серверной карточки и wire совместимость. Не объявлять функцию рабочей до серверной приёмки.

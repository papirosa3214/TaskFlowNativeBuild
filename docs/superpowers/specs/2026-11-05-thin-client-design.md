# Тонкий клиент: экраны с сервера и подключение по QR

Дата: 05.11.2026
Статус: ожидает утверждения владельца. Код по этому документу не менялся.

## Замысел

Владелец выпускает на сервере QR-код, сканирует его телефоном и получает всё
приложение с этого сервера. На телефоне не остаётся бизнес-логики, разбора данных
и описания экранов, а приложение не занимает лишних ресурсов.

## Что значит «ничего не рисуется на телефоне»

Пиксели на экране в любом случае выводит телефон. Поэтому цель такая: **сервер
решает, что показать, а телефон только показывает это готовыми компонентами.**

| Способ | Что приходит | Решение |
| --- | --- | --- |
| Серверные экраны | JSON: экран, блоки, действия | **Выбрано.** Отрисовка остаётся нативной и лёгкой |
| Веб-оболочка | сайт во встроенном браузере | Отклонено: браузер обычно тяжелее нативных экранов и теряет системный вид |
| Трансляция картинки | видео экрана | Отклонено: постоянная сеть и батарея, задержка на каждое касание |
| Код с сервера (JS и подобное) | программа | Отклонено: телефон всё равно исполняет логику, только в более тяжёлой среде |

**Что остаётся на телефоне в любом случае:**
- компоненты дизайн-системы и настройки внешнего вида (тема, шрифт);
- прокрутка, жесты, клавиатура, черновик ввода до отправки;
- камера, микрофон, push-уведомления;
- токен устройства в Keychain и ограниченный кэш.

## Чего не хватает

- **Адрес сервера зашит.** `APIClient.baseURL` — константа с `192.168.1.110:3001`
  (`APIClient.swift:19`), её читают 9 файлов.
- **Нет сканера QR.** Телефон сам выпускает себе токен (`DeviceOpsChannel.swift`,
  `DevicePairing`), но код чужого сервера принять не может.
- **HTTP разрешён только в локальной сети** (`NSAllowsLocalNetworking`). Сервер вне
  неё должен работать по HTTPS.
- **Экраны и логика живут на телефоне.** Всего 93 650 строк Swift, из них
  `Sources/Features` — 52 418. В `AppRoute` 46 вариантов маршрутов.
- **Данные хранятся локально.** Таблицы GRDB `chat`, `message`, `task`,
  `notification` и `SyncEngine`.

## Подключение по QR

1. На сервере владелец выполняет команду или открывает страницу выпуска и получает
   QR. Сейчас выпуск требует уже вошедшего клиента, поэтому для нового телефона
   нужна команда на самом сервере.
2. Телефон показывает при первом запуске один экран «Сканировать QR».
3. После сканирования телефон показывает имя и адрес сервера и просит подтвердить
   подключение. Без этого чужой QR или ссылка могли бы незаметно подключить телефон
   к чужому серверу.
4. Телефон меняет код на токен устройства и сохраняет профиль сервера.
5. Приложение загружает стартовый экран с сервера.

**Профиль сервера:** идентификатор, имя, адрес, токен в Keychain. Активен один
профиль. Смена профиля полностью сбрасывает сессию, сокет и кэш в памяти. Кэш на
диске разделён по серверам.

**Правила безопасности:**
- адрес вне локальной сети принимается только по HTTPS;
- `POST /api/auth/lan` остаётся способом входа только для домашней сети;
- серверные права и политика входа не ослабляются.

## Контракт экрана

Сервер отдаёт смысл, а не внешний вид. За основу берётся уже существующая форма
`AgentComponent` (`name` + `props`).

```json
{
  "contract": 1,
  "screen": "labels",
  "title": "Метки",
  "revision": "a1b2c3",
  "blocks": [
    {
      "id": "label-42",
      "name": "list_row",
      "props": { "title": "Срочно", "icon": "tag", "tone": "accent" },
      "action": { "type": "navigate", "screen": "label", "params": { "id": "42" } }
    }
  ]
}
```

**Запросы**

| Запрос | Назначение |
| --- | --- |
| `GET /api/ui/screens/:screen` | Экран. Поддерживает `ETag`, ответ `304` не гонит данные заново |
| `POST /api/ui/actions/:id` | Действие. Ответ: что обновить, куда перейти, что сообщить |
| Событие `ui.invalidate` в `/ws` | Какие экраны устарели. Телефон перечитывает только открытый |

**Действия:** `navigate`, `call`, `open_url`, `system` (камера, микрофон, вложение).

**Правила контракта**
- **В JSON нет логики.** Никаких условий, циклов и выражений. Если нужно условие,
  его решает сервер и присылает готовый результат. Иначе контракт незаметно
  превратится в язык программирования.
- **Цвета и размеры не передаются.** Только смысловые значения вроде `tone: "accent"`
  и групп шрифта. Правила дизайн-системы и `design-system-guard` продолжают работать.
- **Шапки остаются системными** (`.tfNativeHeader`), как требует проект.
- **Клиент сообщает версию контракта и список известных компонентов.** Сервер не
  присылает то, чего клиент не умеет, а если экран без этого не работает, присылает
  блок «Обновите приложение». Молчаливый пропуск, как сейчас в ленте чата, для
  экранов не подходит: может пропасть кнопка.
- **Мгновенный отклик без логики.** Компонент может сам показать новое состояние
  (переключатель, галочка) и вернуть прежнее, если сервер ответил ошибкой.

**На сервере:** новый раздел `server/src/ui/`. Сборщики экранов читают те же
сервисы и базу, что и текущие маршруты. Текущий API остаётся, пока им пользуются
старые экраны и другие клиенты.

## Кэш и работа без сети

Вместо таблиц предметных данных хранится последний JSON экрана: ключ — сервер,
экран и параметры, размер ограничен, старое вытесняется.

Без сети открываются только уже виденные экраны и только для чтения, с плашкой
«нет связи». Действия без сети не выполняются. **Сегодняшнее офлайн-поведение на
перенесённых экранах станет слабее.**

## Этапы

Каждый этап заканчивается рабочим приложением. Старый код удаляется только после
переноса и оценки владельца.

### 0. Замер

Снять на iPhone память, процессор в простое, расход энергии, трафик и размер
приложения: после запуска, в чате, в списке задач. Нужно отдельное поручение.

**Почему первым:** отрисовка может оказаться не главным расходом. Прецедент
25.10.2026: цикл переподключения сокета за 2 минуты дал 72 подключения к `/ws` и
217 запросов к `/api/tasks`. Кандидаты на проверку: локальная модель диктовки
FluidAudio, LiveKit, встроенный браузер, GRDB, сеть. Целевые числа ставятся после
замера, сейчас их нет.

**Итог:** таблица замеров и решение, что выносить первым.

### 1. QR и профили серверов

Сканер, экран подтверждения, профиль сервера, адрес вместо константы, команда
выпуска QR на сервере. Экраны пока не меняются.

**Итог:** новый телефон подключается к серверу по QR и работает как сейчас. Этап
полезен сам по себе, даже если дальше не идти.

### 2. Пилот: экран «Метки»

Контракт, компоненты, сборщик на сервере. «Метки» (`Sources/Features/Labels`,
505 строк) проверяют всё сразу: список, переход, изменение, обновление по сокету.

**Итог:** экран работает с сервера, новый код сравнивается со старым по замерам
этапа 0. **Здесь решается, идти ли дальше.** Если выигрыша нет, перенос
останавливается: QR останется, а приложение не будет переписано зря.

### 3. Простые экраны

Списки и чтение: настройки, активность, уведомления, обзор, рутины, проекты,
миссии, координация. На этих разделах около 21 000 строк.

### 4. Сложные экраны

| Раздел | Объём | Что остаётся нативным |
| --- | --- | --- |
| Задачи | 11 736 строк | Ввод в форме, черновик |
| Роли и чат | 9 524 строки | Панель ввода, живой вывод. Содержимое ответов уже приходит блоками |
| Планировщик | 4 616 строк | Перетаскивание: палец не может ждать сервер |
| Заметки | 2 732 строки | Редактор |

Эти экраны могут остаться нативными частично, и это нормальный итог.

### 5. Уборка

Удаление перенесённых экранов, моделей, таблиц GRDB, `SyncEngine` и запасных
разборов на телефоне (`ChatRichContent.split`, `MarkdownParser`), если их больше
никто не использует.

## Проверка

- **Контракт:** общие примеры JSON. Сервер проверяет, что собирает такой JSON
  (точечный vitest, `--maxWorkers=4`), телефон — что разбирает его (host-тест без
  симулятора, как `Tools/test_typography_preferences.swift`).
- **Логика:** целевой RED → GREEN.
- **Безопасность QR:** просроченный, использованный и чужой код, HTTP вне локальной
  сети, отказ на экране подтверждения.
- **Интерфейс:** симулятор, UI-тесты и установка на iPhone только по отдельному
  поручению. Внешний вид оценивает владелец.

## Риски

| Риск | Что с ним делаем |
| --- | --- |
| Сервер недоступен — приложение почти бесполезно | Кэш для чтения, понятная плашка |
| Логика не исчезает, а переезжает на сервер, и он становится сложнее | Сборщики отдельно от текущих маршрутов, точечные тесты |
| Контракт разрастается в язык | Запрет логики в JSON, новые компоненты только по необходимости |
| Долго живут два способа отрисовки | Перенос по разделам, старый код удаляется сразу после приёмки |
| Отклик хуже нативного | Локальное мгновенное состояние, `ETag`, кэш, нативные жесты |
| Выигрыша по ресурсам нет | Замер на этапе 0 и остановка после пилота |
| Новый компонент всё равно требует обновить приложение | Версия контракта и блок «Обновите приложение» |

## Не делаем

- Не меняем веб-клиент.
- Не подключаем произвольные серверы: только реализующие этот контракт.
- Не отказываемся от нативных компонентов и дизайн-системы.
- Не заводим карточки в TaskFlow: работа ведётся через реестр и git.

# Вебхуки в разделе «Интеграции»

## Что изменено

Вебхуки — исходящие уведомления TaskFlow: при выбранном событии приложение отправляет HTTP-запрос на совместимый внешний URL-приёмник. Это отдельная интеграция, потому что она связывает события TaskFlow с другим сервисом. Передача в чат Codex — отдельная необязательная возможность.

Настройки iOS читали один и тот же список подписок через `/integrations/webhooks` в двух местах. Экран «Интеграции» давал список и управление, а раздел «Сервер» показывал только статус этого списка. Второй серверный индикатор убран; сводный статус теперь отображается у единственного пункта «Вебхуки» в «Интеграциях».

Точка входа использует ту же строку, иконку, подпись и шеврон, что и Linear/Gmail. Список вебхуков оформлен карточками TaskFlow и показывает события, последнюю доставку, HTTP-ответ, ошибку и состояние передачи в Codex. Секрет приёмника и API-контракт не менялись.

## Как пользоваться

1. Открой **Настройки → Интеграции → Вебхуки**.
2. Нажми **+**, укажи название и HTTP(S)-адрес сервиса, который принимает запросы. Если сервис требует общий ключ, введи его в поле ключа.
3. Выбери события TaskFlow и проверь проект. Форма по умолчанию выбирает `TaskFlow - NewTodoist`; «Все проекты» отправляет события из любого проекта.
4. Проверь заранее введённый ID чата Codex: убедись, что он соответствует нужному чату. Очисти поле, чтобы отключить передачу события в чат.
5. Включи подписку, сохрани её и нажми **Проверить доставку**. На карточке отдельно видны HTTP-доставка, постановка в очередь и подтверждение запуска Codex — одно не означает автоматически другое.

Для редактирования нажми карточку подписки. Удаление требует подтверждения. Секрет не показывается обратно после сохранения.

## Подсказка в приложении

Включи **Настройки → Пользовательские настройки → Подсказки**, затем открой **Настройки → Интеграции → Вебхуки**. Сценарий проводит от строки входа через создание подписки, URL, события и проект к сохранению и тестовой доставке. Вебхук работает с совместимым HTTP(S)-приёмником; Codex — отдельная необязательная передача в чат. Форма заранее подставляет ID чата: для обычной HTTP-доставки подсказка велит вручную очистить поле до выбора соответствующей ветки. Сам выбор ветки ничего в настройке не меняет.

## Ограничение проверки доставки

Модель ответа iOS пока требует верхнеуровневое поле `wake_confirmed`. Если сервер вернёт новый ответ только с вложенным `wake.acked`, клиент может показать ошибку разбора даже после успешной HTTP-доставки. Версию ответа живого сервера в этой работе не проверял; перед исправлением контракта нужен отдельный регрессионный тест.

## Границы проверки

Изменён только iOS-интерфейс и группировка чтения статуса. Сервер, зарегистрированные подписки и внешние URL не менялись. Сторож дизайн-системы прошёл, `git diff --check` чистый, сборка iOS Simulator — `BUILD SUCCEEDED`. XCUITest не запускался; визуальную оценку результата на iPhone делает владелец.

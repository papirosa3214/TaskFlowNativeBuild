# Системный таббар: акцентный выбранный раздел и красный круг «+»

Дата: 18.10.2026 · Файл: `Sources/DesignSystem/Navigation/TFPillTabBar.swift` · Реестр: `LOCK-TABBAR-ACCENT-20261018`

## Результат

В системном таббаре (iOS 27, линза) два изменения:

1. Выбранный ярлык с подписью — в `Color.tfRed`. Работает штатно: `.tint(Color.tfRed)` на `TabView`.
2. Круглая кнопка «+» справа — салоново-красная (`Color.tfRedSolid`), 62 pt, ровно на месте системного prominent-круга.

Кадры: `2026-10-18-tabbar-accent/01-selected-tab-accent.png` (акцент ярлыка), `2026-10-18-tabbar-accent/02-final-red-circle.png` (итог).

Домик, папка и чат используют парные стандартные SF Symbols: `house` /
`house.fill`, `folder` / `folder.fill`, `ellipsis.bubble` / `ellipsis.bubble.fill`.
Неактивный вариант — белый контур, активный парный вариант — красная заливка. Календарь сохраняет постоянную дату: чёрную на красной
заливке и белую внутри белого контура. Проверка результата — кадр экрана проектов в симуляторе: `2026-10-18-tabbar-accent/11-projects-symbol-pairs.png`.

## Почему круг наш, а не системный

Системный prominent-круг покрасить нечем. API цвета у `TabRole.prominent` нет ни в SwiftUI, ни в UIKit — проверено восемью сборками:

| Способ | Результат |
|---|---|
| `.tint(Color.tfRed)` на TabView | красит только ярлык, круг игнорирует |
| Своя подпись `Label` с красной иконкой | игнорируется, рисуется системный SF Symbol |
| Глобальный акцент приложения (`AccentColor.colorset` + `ASSETCATALOG_COMPILER_GLOBAL_ACCENT_COLOR_NAME`) | `NSAccentColorName` в Info.plist подтверждён, цвет в `Assets.car` есть — красит ярлык, не круг |
| `window.tintColor` через UIViewRepresentable | без эффекта |
| `UITabBarAppearance.backgroundColor` | ломает стекло iOS 26+, панель становится прозрачной |
| Своя кнопка `.glassProminent` + `.glassEffect(.tint)` поверх | закрывает системный «+»; стиль добавляет ~27 pt полей, круг выглядит «раздутым куском» |
| Диск в `.background()` под панелью | стекло преломляет его в радужное пятно |
| Роль `.search` вместо `.prominent` | плюс уезжает внутрь пилюли пятой вкладкой |

Два независимых исследования (англоязычные и русскоязычные источники) дали тот же вывод: официального способа нет; настройки «Accent Color» на iOS/iPadOS не существует (только macOS). Рабочий путь для системного акцента — `tabViewBottomAccessory` (iOS 26.1+), но он не про prominent-круг.

## Геометрия круга — из иерархии, не на глаз

Раньше координаты подбирались по кадру, из-за чего круг то расходился с системным, то выглядел «наложенным». Сейчас взяты из UI-иерархии симулятора (Xcode MCP, iPhone Air, 420×912 pt):

```
TabBar       {0, 829, 420×83}
Button «Создать»  {337, 829, 62×62}   ← система
```

То есть 62 pt и по 21 pt от правого и нижнего края. Наш круг повторяет ровно эти числа (`createCircleSize = 62`, `createCircleEdgeInset = 21`), без `GeometryReader` и без вычислений от `safeAreaInsets`.

Проверка после сборки — замер по пикселям кадра (`ffmpeg` → raw RGB, порог по красному):

| | Замерено | Задано | Система |
|---|---|---|---|
| Диаметр | 62.0 pt | 62 | 62 |
| Отступ справа | 21.3 pt | 21 | 21 |
| Отступ снизу | 21.3 pt | 21 | 21 |
| Центр | (367.9, 859.9) | (368, 860) | (368, 860) |

## Оговорки

- Без системной prominent-вкладки не получится: четыре ярлыка растягиваются на всю ширину и «Чат» уезжает под круг. Поэтому системная вкладка остаётся, а наш круг лежит поверх неё. Это компромисс: слой приложения поверх системного.
- Доступность: свой `Button` виден VoiceOver рядом с системным «Создать». Раньше стояло `.accessibilityHidden(true)` — снято, чтобы круг оставался единственным активным элементом с нашим `onCreateTap`.
- Координаты сняты на iPhone Air. На другом устройстве отступы считаются от края экрана, поэтому позиция останется корректной, но 21 pt — это константа этой модели, а не API-константа.

## Два состояния системных иконок — итоговая реализация

Неактивное состояние — белый контур SF Symbol, активное — его залитая красная пара. Все пары передаются нативной панели через `UITabBarItem.image` и `selectedImage` сразу для всех вкладок, включая ещё не открытые. Используются `house` / `house.fill`, `folder` / `folder.fill`, `ellipsis.bubble` / `ellipsis.bubble.fill`.

Символы предварительно преобразуются в шаблонные растровые изображения, чтобы SwiftUI не подставлял залитый вариант вместо запрошенного контура. Цвет задаёт нативный tab bar. Собственная маска и таймер анимации отсутствуют; сменой состояний управляет система. Точная промежуточная геометрия во время перетаскивания линзы этим прогоном не проверена.

# Наводящие карточки «Входящих» — 29.10.2026

## Задача

Владелец: «чтобы все-таки эти входящие как-то были наводящими уже изначально карточками, которые как бы мне сразу давали понять… Нажимаю на нее и уже проваливаюсь там задачу, я уже знаю, что в задаче делать или кому писать, грубо говоря».

Было: карточка во «Входящих» — это название задачи, проект, роль, срок и «просрочено». Что с задачей делать, из карточки не видно: чтобы понять, приходилось открывать задачу и вникать в неё заново.

Стало: под названием задачи — одна строка о том, что с ней делать прямо сейчас. Карточка отвечает сама.

## Что сделано

### Сервер (`New-Todoist`, PR #31, ветка `feature/attention-card-context`)

- `server/src/lib/attentionContext.ts` (новый) — чистая функция `attentionHint()`. Порядок источников:
  1. **вопрос роли** → «Нужен ваш ответ: …»;
  2. **причина блокировки** (`tasks.blocked_reason`) — она и у задач «На проверке» объясняет, что ждёт решения владельца;
  3. **свой источник группы**: «В работе» — текущий шаг; «На проверке» — вердикт проверки (`approved:` / `changes_requested:`), иначе результат последнего закрытого шага; «Заблокировано» — результат незакрытого шага;
  4. **первая часть описания** — последний запас, без заголовка раздела («## Работа» на карточке не показывается).

  Строка всегда одна: переводы строк склеены, длинный текст обрезан на 120 символах (две строки карточки на телефоне).
- `server/src/routes/attention.ts` — `GET /api/attention` отдаёт в каждой задаче новое поле `hint`. Старый клиент поле не заметит; новый клиент со старым сервером — тоже (поле необязательное).

Живой пример (боевая база .110, 29.10.2026):

```
Заблокировано
  Тип widget с вложенным table — клиент iOS его не рисует
    Проверка заблокирована: 3 захода без вердикта; нужно решение владельца.

  Какие правила роль реально получает при старте в чате
    Проверка заблокирована: заход не оставил нового сохранённого результата; автоматический повтор запрещён…

На проверке
  Инфра-панель: чат агента — MiniMax по умолчанию
    Достигнут лимит доработок плана — требуется решения владельца

  Выгружаю за предыдущий день всю информацию о действиях ролей
    approved: Проверено по артефактам, а не по отчёту роли: CSV в ветке роли содержит ровно 56 отказов…
```

### Клиент (`TaskFlowNativeBuild`, этот репозиторий)

- `Sources/Core/Models/AttentionFeed.swift` (новый) — модели ответа `GET /api/attention` перенесены из экрана (чтобы контракт проверялся на хосте, без симулятора). В модели — поле `hint`, правило `hintLine` (пустая строка не рисуется), новые поля строки (`role_id`, `priority`, `subtask_total`, `subtask_done`) и `roleInitials` для аватара.
- `Sources/Features/Attention/AttentionScreen.swift` — карточка переведена на строку дизайн-системы `TFTaskRowContent`, как в остальных списках приложения: аватар роли слева, название, наводящая строка (слот описания, две строки), ряд меток (проект, приоритет, шаги, роль, возраст, просрочено). Свой шеврон у строки убран — у `NavigationLink` он свой, и вместе они давали два шеврона подряд. Шапки секций получили общий фон карточек и убрали линейку под заголовком (была чёрная полоса над серыми карточками).
- `Sources/DesignSystem/Components/TFTaskRow.swift` — у `TFTaskRowContent` появился необязательный параметр `descriptionLines` (по умолчанию 1, то есть на других экранах ничего не меняется): наводящей строке нужны две строки.

По кадру с телефона (29.10.2026) видно и главное: подсказка того же белого цвета, что и название, из-за чего иерархия «что это / что делать» не читалась. Теперь название — заголовок строки, наводящая строка — приглушённая (как описание в остальных списках).

### Сервер: экземпляр рутины закрывается сам (PR #34)

По кадру с телефона стало видно, что одна из карточек «Входящих» — карточка рутины «Ежедневный отчёт об ошибках в вызываемых инструментах ролей» — висит «на проверке» с прошлого дня, хотя её работа давно одобрена критиком. Она не только занимает место во «Входящих», но и **блокирует следующий запуск рутины**: слот 29.10 в 08:00 был пропущен с причиной «прошлый экземпляр не закрыт».

- `server/src/runtime/schedules/store.ts` — `closeApprovedInstances()`: у активных рутин закрывает карточку текущего экземпляра, если работа по ней одобрена (`criticApproved` — та же проверка, по которой приложение показывает «одобрено»). Незакрытая работа не трогается.
- `server/src/runtime/schedules/tick.ts` — вызов на каждом проходе планировщика.

### Сервер: подсказка не повторяет название (PR #35)

У части задач незакрытый шаг назван так же, как сама задача («1. Единый допуск запуска…» / «4. Единый допуск запуска…») — подсказка дословно повторяла заголовок карточки. Теперь такой источник отсекается наравне с описанием.

## Ограничения

- **Симулятор, телефон, кадры и UI-тесты не трогали** — по прямому указанию владельца от 25.10.2026. Вид карточки оценивает владелец; проверки логики визуальной приёмки не заменяют.
- Полный набор серверных тестов на .110 не гоняли (правило: только целевые файлы, `--maxWorkers=4`); гейт по регрессиям гоняет CI на GitHub.
- Серверные тесты изолированы (`test/setup.ts` поднимает временную базу) — боевая база не затрагивается.
- Наводящая строка — это то, что сервер знает о задаче на момент запроса. Если у задачи нет ни причины блокировки, ни шагов, ни описания — строки не будет, карточка останется такой, как была.

# Наводящие карточки «Входящих» — 29.10.2026

## Задача

Владелец: «чтобы все-таки эти входящие как-то были наводящими уже изначально карточками, которые как бы мне сразу давали понять… Нажимаю на нее и уже проваливаюсь там задачу, я уже знаю, что в задаче делать или кому писать, грубо говоря».

Было: карточка во «Входящих» — это название задачи, проект, роль, срок и «просрочено». Что с задачей делать, из карточки не видно: чтобы понять, приходилось открывать задачу и вникать в неё заново.

Стало: под названием задачи — одна строка о том, что с ней делать прямо сейчас. Карточка отвечает сама.

## Что сделано

### Сервер (`New-Todoist`, PR #31, ветка `feature/attention-card-context`)

- `server/src/lib/attentionContext.ts` (новый) — чистая функция `attentionHint()`. Порядок источников:
  1. **вопрос роли** → «Нужен ваш ответ: …»;
  2. **причина блокировки** (`tasks.blocked_reason`) — она и у задач «На проверке» объясняет, что ждёт решения владельца;
  3. **свой источник группы**: «В работе» — текущий шаг; «На проверке» — вердикт проверки (`approved:` / `changes_requested:`), иначе результат последнего закрытого шага; «Заблокировано» — результат незакрытого шага;
  4. **первая часть описания** — последний запас, без заголовка раздела («## Работа» на карточке не показывается).

  Строка всегда одна: переводы строк склеены, длинный текст обрезан на 120 символах (две строки карточки на телефоне).
- `server/src/routes/attention.ts` — `GET /api/attention` отдаёт в каждой задаче новое поле `hint`. Старый клиент поле не заметит; новый клиент со старым сервером — тоже (поле необязательное).

Живой пример (боевая база .110, 29.10.2026):

```
Заблокировано
  Тип widget с вложенным table — клиент iOS его не рисует
    Проверка заблокирована: 3 захода без вердикта; нужно решение владельца.

  Какие правила роль реально получает при старте в чате
    Проверка заблокирована: заход не оставил нового сохранённого результата; автоматический повтор запрещён…

На проверке
  Инфра-панель: чат агента — MiniMax по умолчанию
    Достигнут лимит доработок плана — требуется решения владельца

  Выгружаю за предыдущий день всю информацию о действиях ролей
    approved: Проверено по артефактам, а не по отчёту роли: CSV в ветке роли содержит ровно 56 отказов…
```

### Клиент (`TaskFlowNativeBuild`, этот репозиторий)

- `Sources/Core/Models/AttentionFeed.swift` (новый) — модели ответа `GET /api/attention` перенесены из экрана (чтобы контракт проверялся на хосте, без симулятора). В модели — поле `hint` и правило `hintLine`: пустая строка на карточке не рисуется.
- `Sources/Features/Attention/AttentionScreen.swift` — под названием задачи рисуется наводящая строка: `.tfText(.action)`, основной цвет текста, две строки.

Роль («кому писать») на карточке уже была — она осталась в ряду меток.

## Ограничения

- **Симулятор, телефон, кадры и UI-тесты не трогали** — по прямому указанию владельца от 25.10.2026. Вид карточки оценивает владелец; сборка и проверки логики визуальной приёмки не заменяют.
- Полный набор серверных тестов на .110 не гоняли (правило: только целевые файлы, `--maxWorkers=4`); гейт по регрессиям гоняет CI на GitHub.
- Серверные тесты изолированы (`test/setup.ts` поднимает временную базу) — боевая база не затрагивается.
- Наводящая строка — это то, что сервер знает о задаче на момент запроса. Если у задачи нет ни причины блокировки, ни шагов, ни описания — строки не будет, карточка останется такой, как была.

# Голос Помощника и экран iPhone

## Согласованный сценарий

Звонок начинается из чата «Помощник». Владелец явно запускает системную ReplayKit-трансляцию, сворачивает TaskFlow, открывает другое приложение и продолжает тот же голосовой разговор. Только просмотр; управление устройством не добавляется. Другой чат не переназначает текущий звонок.

## Архитектура

Переиспользуется LiveKit/Gemini Live: Broadcast Upload Extension → IPC LiveKit через App Group → screenShareVideo той же комнаты → video_input голосового AgentSession → Gemini realtime video рядом с текущим аудио. Микрофон остаётся у существующего LocalAudioTrack; расширение игнорирует оба вида аудиобуферов ReplayKit. Снимки не выдаются за доставленные текстовыми обещаниями.

В iOS проект добавляется background audio mode. Корневая SecretaryVoiceViewModel уже владеет соединением вне экрана; уход в фон сам по себе его не завершает. Live Activity используется только для состояния и возврата к разговору; не как механизм удержания процесса.

Начало трансляции — системный picker/Пункт управления, остановка — системный интерфейс или кнопка TaskFlow. При завершении звонка трансляция останавливается, готовность расширения сбрасывается. Без активного звонка расширение не передаёт кадры.

## Найденные факты и ограничения

- `project.yml`: LiveKit уже подключён, целевая iOS 18; UIBackgroundModes содержит только location. Нового голосового движка не требуется.
- В установленных профилях команды RUD4WAP9DF `LocalProvision=true`, семидневный срок, App Groups пока отсутствуют. Это факт о профиле, а не доказательство запрета ReplayKit. Текущая таблица Apple отмечает App groups для ADP, ADEP и бесплатного Apple Developer.
- Подписываемого профиля Broadcast Upload Extension сейчас нет. Реальная доступность группы и нового bundle ID потребует provisioning; unsigned/static проверка не доказывает подпись и работу на iPhone.
- Голосовой backend на .110 — LiveKit Agents 1.8.3, Google RealtimeModel gemini-3.8-live. Установленный SDK поддерживает RoomOptions.video_input, participant_identity и push_video → image/jpeg → send_realtime_input(video=...). В текущем worker video_input по умолчанию выключен.
- Текстовый Pi-чат сейчас передаёт `session.prompt(text)`; названия вложений в истории не являются vision-входом. Этот путь не подменяет приоритетный голосовой сценарий.
- Поддержка фонового аудио не гарантирует разговор поверх приложения, которое само перехватывает микрофон/аудиосессию. Системные прерывания и защищённый контент остаются ограничениями iOS.

## План проверки

Целевой Python unit вызывает реальный entrypoint с замоканными внешними сервисами: на старом worker отсутствие видеовхода должно давать RED, после включения — GREEN; аудио, привязка owner и комната остаются прежними. Подсказка проверяется целевым тестом HintCenter без симулятора. Проверки Swift — без запуска UI. Проверить xcodegen, plist/entitlements, diff и дизайн-сторож. Установка, захват экрана и live-разговор не разрешены и не считаются проверенными.

## Реализовано и проверено

- В голосовом экране появилась кнопка системной трансляции и подсказка. SDK picker скрывает кнопку микрофона ReplayKit; в Пункте управления его также нужно оставлять выключенным. Расширение использует штатный LKSampleHandler: microphone samples не поддерживаются uploader, а appAudio отключён принимающей стороной. Собственный параллельный микрофон не создаётся.
- BroadcastManager автоматическая публикация отключена; текущая SecretaryVoiceViewModel публикует screenShareVideo только в свою подключённую Room после системного старта. Завершение звонка останавливает трансляцию. Без звонка нет принимающего IPC-сокета/комнаты; SDK закрывает расширение с ошибкой соединения.
- Добавлен audio background mode; LiveKit сам настраивает playAndRecord при включении микрофона. Переход в фон не вызывает stop. Привязка к исходному чату остаётся в существующей SecretaryVoicePresentation.
- Существующая TaskActivityWidget использована для голоса: голосовые активности отделены optional voiceChatID от задач, не подписываются на обновления задач; показывают голос/экран, без ложных процентов прогресса, открывают действующий разговор по taskflow://voice. Отсчёт идёт от начала звонка и не сбрасывается при речи.
- Signed device build через XcodeBuildMCP завершился успешно, включая TaskFlowBroadcast. Профили обоих бандлов декодированы: LocalProvision=true, команда RUD4WAP9DF, App Group group.com.maksim.taskflow.native; codesign --verify --strict обеих целей — 0. Подпись не является препятствием в этой конфигурации. Последняя сборка после финальных UI-правок также успешна.
- 24 целевых Python-теста — GREEN. Поведенческий тест entrypoint сначала упал на старом коде; отдельный тест кодирования сначала выявил отсутствие Pillow. Установлена Pillow 13.0.0, requirements содержит images extra.
- Целевая подсказка через реальные HintCenter/HintScenarios: RED (сценария нет) → GREEN, macOS Swift Package без симулятора. Файлы в /tmp/taskflow-screen-hint-tests, лог /tmp/taskflow-screen-hint-green.log. Два существующих теста SecretaryVoicePresentation дополнительно проверяют, что сворачивание не меняет чат и не создаёт новый разговор.
- Реальный Gemini Live через штатный HTTPS proxy прочитал код 7392 из непрерывного синтетического JPEG-видеопотока: «seven three nine two». Это тест провайдера с синтетическими данными, не захват экрана владельца и не весь путь с iPhone. Прямая проба без proxy дала ожидаемый региональный отказ; штатный voice-сервис использует proxy.
- xcodegen generate, Swift parse, git diff --check и дизайн-сторож — PASS. На фоне сборки есть прежние предупреждения других файлов, новых compiler errors нет.

Серверная часть: commit 35d18550, ветка feature/voice-screen-share-20261029, PR https://github.com/papirosa3214/New-Todoist/pull/18. До слияния/перезапуска worker видео в уже работающем сервисе не включено. Pillow установлена в существующее venv; HTTP-сервер для этой правки перезапускать не требуется.

## Граница приёмки

В этой реализации экран идёт в голосовой разговор Помощника из исходного чата. Текстовые vision-входы остальных Pi-ролей не добавлены. Физический iPhone не устанавливался, трансляция и микрофон владельца не запускались. Полный сценарий «уйти в другое приложение и продолжить говорить о видимом» остаётся для проверки владельцем; код, сборка и синтетический provider smoke не заменяют её.

# Сессия: финальный текст ответа не теряется в `message_end` (14.11.2026)

## Что было

`SessionLiveTurn.apply` для `message_end` клал хвост ответа только в последний
пункт хода:

```swift
guard let full = payload["text"]?.sessionString, case .text? = items.last else { return }
items[items.count - 1] = .text(full)
```

Из-за этого финальный текст новой сессии пропадал в трёх случаях:

1. после текста пришли размышление или шаг инструмента — последним пунктом уже
   не текст, хвост не применялся, и разметка ответа не регистрировалась;
2. ответ целиком был только в `message_end` (ни один кусок не принёс
   серверного текста, например после переподключения) — пунктов не было, и
   текст не появлялся вообще;
3. два сообщения в одном ходе: `assistant_text_delta` подменял текст
   предыдущего пункта, поэтому второй ответ затирал первый.

## Что сделано

Только в сессиях (`Sources/Features/Sessions/SessionLiveTurn.swift`); разметка
по-прежнему приходит готовой с сервера и на телефоне не разбирается — телефон
лишь кладёт блоки в реестр `ChatLiveBlockRegistry` и показывает пункт с
серверным текстом (тонкий клиент, правило 13.11.2026).

- у хода появился `textItemIndex` — пункт текста текущего сообщения;
- `assistant_text_delta` дописывает текст в свой пункт и только при отсутствии
  такого пункта заводит новый: текст следующего сообщения не подменяет
  предыдущий, порядок пунктов сохраняется;
- `message_end` кладёт хвост в пункт своего сообщения (даже если последним
  стал размышление или шаг), а если пункта нет — создаёт ответ, когда до этого
  не было ни одного серверного куска;
- хвост кладётся только вместе с подготовленной серверной разметкой: без
  `blocks` показанное размеченное начало не подменяется голой строкой (иначе
  экран показал бы «Не удалось получить подготовленное содержимое»); текст не
  теряется и при полностью пустом ходе;
- `register` возвращает, легла ли разметка в реестр (`@discardableResult`),
  чтобы разметка и текст пункта были согласованы;
- на конце сообщения `textItemIndex` сбрасывается, поэтому следующий текст
  встаёт новым пунктом.

Опубликованная идентичность хода (`identity`, `scope`, решение d0a063ef) не
тронута. Остановка хода, восстановление снимком и лента истории не менялись.
Роли (`Sources/Features/Roles/*`) не тронуты: сессии и чаты ролей остаются
раздельными потоками, перенос решений ролей — только отдельной работой.

## Проверки

Стенд без симулятора (`Tools/test_session_live_turn.py`, XCTest на macOS,
настоящие исходники `SessionLiveTurn.swift` и моделей `Core`).

Новые тесты в `Tests/SessionLiveTurnTests.swift` (реальный путь `apply`
событий, настоящие блоки `doc`):

- хвост встаёт, когда последним пунктом стало размышление, и разметка
  регистрируется в реестре;
- хвост встаёт, когда последним пунктом стал шаг инструмента, шаг остаётся на
  месте;
- ответ появляется, когда ни один кусок не принёс серверного текста (без
  заглушек и дублей);
- ответ создаётся, когда у хода ещё нет ни одного пункта (переподключение);
- два сообщения: второй текст не подменяет и не теряет первый, порядок
  «ответ → шаг → ответ», разметка обоих ответов на месте;
- `message_end` без `blocks` не подменяет показанное размеченное начало.

Итог: RED на исходнике HEAD (все шесть падали с ожидаемыми сообщениями,
например `("["Первый", "Второй полностью"]") is not equal to ("["Первый
полностью", "Второй полностью"]")`) → GREEN после правки (шесть из шести).
Сторож дизайн-системы `--diff HEAD` — чисто. `Tools/test_chat_live_block_scope.py`
(области разметки) — 9/9 зелёные.

  только серверный текст. Падал и на HEAD до этой правки — к хвосту
  `message_end` отношения не имеет, в этой работе не трогался.

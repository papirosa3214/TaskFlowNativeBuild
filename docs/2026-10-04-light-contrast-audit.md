# Повторный аудит светлого текста — 04.10.2026

Владелец заметил, что карточка задачи и вложенные окна остаются бледными после первой правки общих tfSub/tfDim. Проверка выполнена с apple-design; размер и начертание шрифтов сохранены.

Первая правка действовала на все места, использующие tfSub/tfDim, но не затрагивала отдельные цвета, системные secondary/tertiary, дополнительную прозрачность и значения LabeledContent. Поэтому утверждение «весь текст во всём приложении исправлен» было бы неточным.

| Найденное место | Изменение только в светлой теме |
| --- | --- |
| Описание, названия подзадач, ввод комментария | Основной цвет tfText вместо вторичного; размеры прежние |
| Заблокированная задача, эскалация модели | Непрозрачный оранжевый вместо дополнительной альфы 0,8 |
| Связанные задачи и их выбор | Читаемый вторичный цвет вместо системного серого |
| Шаг плана: роль, состояние, круг доработки, пояснения | Явный tfSub для значений и мелких пояснений |
| Приоритеты в списках/значках | Адаптивные цвета вместо одинаковых в обеих темах hex |
| Проекты/метки с произвольными цветами сервера | Цвет текста затемняется до ≥7:1 на tfCard2; исходные API-цвета, заливки и аватары не меняются |
| Пилюли и акцентные теги | Основной тёмный текст на прежней цветной подложке |
| Календарь: дни вне текущего периода; подписи графика | Дополнительная прозрачность текста убрана |
| Метрики проектов, проценты графика | Применено адаптивное затемнение текстового цвета |
| Голосовые сообщения, темы проекта, таблица заметки | Вторичный/третичный цвет адаптирован к читаемым токенам |
| Стрелки редактора срока | Убрана альфа 0,35 на светлом фоне |

Общий UITextView-редактор раньше обновлял внешние атрибуты только при изменении строки. Он теперь синхронизирует также оформление вне активного ввода; фокусируемый текст не перезаписывается. Программная смена оформления временно отключает delegate, чтобы не выдавать её за пользовательское изменение выделения.

## Проверка и границы результата

Unit tests проверяют ≥7:1 для нейтральных и произвольных текстовых цветов на трёх базовых поверхностях, ≥4,5:1 для приоритетов/предупреждений, непрозрачность в светлой теме и сохранение прежних тёмных приоритетов/тональности/альфы.

XCUITest использует accessibilityIdentifier/label. Основная карточка, описание, сведения, подзадачи, активность и окно связывания смотрятся на реальных данных .110. Шаг совместного плана и редактор срока проверяются отдельно с локальным fixture-сервером; это проверка интерфейса, а не приёмка живого исполнения роли. Тесты не выбирают дату, не связывают задачи, не запускают роли и не редактируют содержимое живой задачи. Открытие редактора срока автоматически задаёт дату, поэтому проверка этого окна проводится на fixture.

Аудит источников охватывает перечисленные общие компоненты и экраны. Это не визуальная приёмка каждого возможного маршрута/состояния приложения. Системные меню, отключённые элементы и цветовые значения на сервере не переделывались. Контраст на произвольном материале/изображении не гарантируется тестами трёх базовых поверхностей.

Физический iPhone не обновлялся. Итоговые кадры — в `docs/2026-10-04-light-contrast-audit/`.

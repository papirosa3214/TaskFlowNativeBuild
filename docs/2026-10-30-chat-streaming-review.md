# Чат со стримингом: разбор, сравнение с рецептом и что не покрыто

30.10.2026. Разбор по поручению владельца: изучить, как устроен чат со
стримингом в TaskFlow iOS, сравнить с присланным рецептом «плавный чат со
стримингом», зафиксировать результат. Механику не переписывали — работали по
решениям владельца (24.10, 26.10, 30.10.2026).

## 1. Как устроено сегодня

Экран чата один — `RoleChatsScreen.swift` (`RoleChatRoomScreen`). Старый чат
(`ChatScreen` и обвязка) удалён как мёртвый код в тот же день.

| Слой | Где |
|---|---|
| Идентичность сообщения | серверный UUID (`RoleChatMessage.id`), порядок — `sequence` (rowid) |
| Вставка в ленту | `RoleChatMessageOrder.inserting` — по `sequence`, без пересортировки |
| Строка ленты | `RoleChatRowID`: `msg:<id>` / `turn:<playbackID>`; сообщение, закрывшее ход, занимает строку хода — строка не пересоздаётся |
| Порядок | `ChatTimelineProjection`: серверный порядок, живой ход — после своего `trigger_message_id`, ответ с остановкой — после своего вопроса |
| Транспорт | `RealtimeClient` (WebSocket), переподключение, keepalive |
| Склейка событий | `ChatEventCoalescer`, окно 80 мс — всё за окно применяется одним обновлением |
| Дельты хода | `RoleChatLiveTurnState.apply(_:)`, разрыв нумерации → снимок целиком |
| Проявление текста | `RoleLiveTextPacer`, 60–900 знаков/с, целевое отставание 0,6 с |
| Рост хода | `RoleLiveTurnGrowth.accepts` — показанный список только растёт |
| Прокрутка | `defaultScrollAnchor(.bottom, for: .sizeChanges)` с признаком `chatFollowsBottom` по фазе прокрутки; `scrollPosition` без якоря |
| Панель ввода | одно поле (`promptField`), меняется окружение (капсула ↔ полная панель) |

Решения владельца, на которые всё опирается: нативные механизмы Apple, без
своей механики перемещения ленты (24.10); «убери всё наше лишнее… пусть будет
нативная хрень» (26.10); панель ввода с двумя видами — динамическое окно (30.10).

## 2. Сравнение с рецептом

| Пункт рецепта | В TaskFlow | Вердикт |
|---|---|---|
| Постоянный id сообщения, ИИ дописывает то же сообщение | UUID + `sequence`; живой ход — отдельная строка `turn:<playbackID>`, обновляется на месте | Эквивалент, строка ответа не пересоздаётся |
| Хронологический массив, новое — в конец | серверный порядок, ход — после своего якоря, неотправленные — в хвосте | Эквивалент |
| `scrollTo(lastID, anchor: .bottom)` на каждый токен | не используется: «быть у низа» держит `defaultScrollAnchor`, позиция — `ScrollPosition` | Совет неприменим: императивный скролл на токен — то «лишнее», что владелец велел убрать |
| Не анимировать вставку букв | анимации вставки строк нет (запрещена сторожем `Tools/test_chat_native_scrolling.py`) | Совпадает |
| Автоскролл выключается, когда владелец листает вверх | `chatFollowsBottom` меняется только от фазы прокрутки владельца | Совпадает |
| UIKit, обновление ячейки вместо `reloadData` | приложение на SwiftUI, UIKit-списка в чате нет | Неприменимо |
| Инвертированный список | не используется | Переписывание против решения владельца |
| Троттлинг 30–50 мс | склейка 80 мс + пейсер 60–900 знаков/с | Совпадает, сильнее |

## 3. Чего рецепт не покрывает — и что с этим сделано

Настоящие причины «шатания» ленты (разбор 25–26.10,
`docs/2026-10-25-chat-shake.md` и `2026-10-25-chat-window-behaviour.md`) и их
состояние на 30.10.2026:

| Причина | Состояние |
|---|---|
| Живой ход укорачивался более коротким снимком (снимок приходит и позже дельт) | закрыто: `RoleLiveTurnGrowth.accepts` |
| На смене «живой пузырь → готовое сообщение» шаги меняли форму (полоса с превью ↔ голая строка) — усадка на десятки-сотни пунктов | закрыто: `closedTurnMessageIDs`, шаги рисуются формой живого пузыря |
| Текст ответа показывался дважды (живой пузырь и готовое сообщение) | закрыто: сообщение скрыто, пока ход доигрывает, и занимает его строку |
| Ответ на вопрос, прерванный новым сообщением, вставал ниже нового вопроса | закрыто: `anchorMessageID` — ответ стоит сразу после своего вопроса |
| Работа прежнего хода пропадала, когда начинался новый | закрыто: `parkLiveTurn` — прежний ход доигрывает на своём месте |
| `replyContext` искал вопрос перебором всей ленты в каждой строке (O(n²)) | закрыто: `Self.replyExcerpts(from:)`, один проход на кадр |
| Липкий `isPositionedByUser` | закрыто: признак `chatFollowsBottom` по фазе прокрутки |
| Клавиатура не ставила каретку: две панели ввода с двумя полями подменяли поле | закрыто: одна панель, одно поле (`docs/2026-10-29-chat-composer-focus.md`) |

## 4. Что осталось открытым

- **Высота строки в конце хода**: у готового сообщения добавляется подвал
  (использование, кнопки), у живого пузыря его нет — один скачок на конец хода.
- **Вложенные списки по `\.offset`** (сегменты живого пузыря, блоки markdown,
  пункты чек-листа) — индекс как id пересоздаёт строки при вставке в середину.
- **Стоимость кадра при проявлении**: свой `TimelineView` на блок, пересборка
  `Text` на каждом кадре.
- **Замеры на устройстве**: `ChatScrollTrace` живёт только в `DEBUG`, а на
  телефон ставится Release-сборка (`LOCK-INSTALL-RELEASE-20261029`), поэтому
  числа смещений и высот с телефона сейчас не снимаются. Если понадобится —
  отдельная отладочная сборка на один прогон.

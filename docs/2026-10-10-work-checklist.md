# Рабочие этапы исполнителя в iOS — 10.10.2026

## Что реализовано

Нажатие названия существующей подзадачи раскрывает её рабочие этапы прямо под строкой; повторное нажатие сворачивает. Список составляет и обновляет исполнитель, владелец только смотрит. Выполненные этапы помечены галочкой, текущий — «Сейчас», ожидающие — пустым кружком; показано «Выполнено N из M». В режиме правки названий сохранён существующий редактор.

В окне узла командного плана тоже добавлен сворачиваемый блок «Рабочие этапы исполнителя». Назначение, запуск и сдача не изменены. Ревью подзадачи не добавлено.

Данные читаются из GET `/api/subtasks/:id/work-plan`. Обновление — через существующее событие `task:updated`; при открытии, reconnect и возврате приложения запрос восстанавливает состояние. Если плана нет, показано «Исполнитель ещё не составил рабочие этапы». При ошибке показана ошибка; этапы другого слота не отображаются. Устройством план не придумывается.

## Инструмент и инструкция исполнителям

Серверный коммит `e22179dd`, ветка `codex/subtask-work-checklist` на .110, worktree `/home/maksim/.local/state/taskflow-runs/worktrees/codex-subtask-work-checklist`. Патч рядом: [server.patch](2026-10-10-work-checklist/server.patch).

`taskflow_work_plan` привязан к текущему слоту: чтение без items; запись всего списка с base_revision. Данные сохраняются в отдельной таблице, миграция `129_subtask_work_plans`. Права: текущий исполнитель работающего слота; закрытый/чужой слот не изменить. Устаревшая версия → 409. Отметки не меняют состояние/сдачу подзадачи.

Каждый запуск/продолжение слота получает инструкцию: до работы составить небольшой конкретный план (обычно 3–7 этапов), отметить текущий этап, отмечать выполненное по факту, дополнять список, сохранять выполненное при продолжении. Инструмент включён в финальные customTools; инструкция использует его слой в resolver, доступный для просмотра. Индивидуальные промпты участников не перезаписаны. Новый инструмент и инструкции начнут использоваться после публикации серверной части; существующим запускам задним числом ничего не отправлено.

Сторож хранения выполняет пробную запись/обновление/чтение с откатом, при сбое создаёт до одной задачи в «Серверных уведомлениях» в сутки. Реестр server docs/watchers.md обновлён.

# Лента чата с ролью: идентичность строк, порядок сообщений, московское время — 22.10.2026

## Поручение

Владелец 22.10.2026: «у меня отвратительно работают чаты, бывают криво встают мои
сообщения непоследовательно по времени… куда-то вечно уезжает монитор, экранчик,
то есть лента куда-то дотолова вниз, а там уже текста нет, но он всё равно
почему-то там где-то».

## Причины (по коду и по живой базе)

1. **Строки ленты делили один id.** `RoleChatsScreen.swift`, `feedItemID(for:)`
   строил id как «reply:автор:на что ответ». Такая пара НЕ уникальна: одна роль
   отвечает на одно сообщение несколькими строками — сам ответ и служебные
   строки координации («Ответ получен», «Ход завершился ошибкой»).
   В живой базе (`taskflow.db`, чат `c1d2ecf3`) у роли `code_orchestrator` на
   один ответ приходится **6** строк, на другом — 5; всего 508 сообщений с
   `reply_to_message_id`, 15 групп-дубликатов. SwiftUI на одинаковых id в
   `ForEach` переиспользует строки: пузырь одного ответа встаёт на место
   другого, текст пропадает, а визуально он «где-то ещё». Это и есть и
   «текста нет, но он где-то», и «криво встают по времени».
2. **На каждое событие сортировалась вся лента.** `insertIncoming` и `deliver`
   вызывали `RoleChatMessageOrder.sorted(messages)` — компаратор разбирал даты
   заново для каждой пары, а лента пересчитывается на каждом снимке живого
   ответа (сервер шлёт их раз в 150 мс).
3. **Живой ход прятал лишние сообщения.** `visibleMessages` скрывал любое
   сообщение того же автора, попавшее в окно времени хода, а не то сообщение,
   которое ход закрыло. Ответ роли мог пропасть из ленты целиком.
4. **Живой ход подавлялся служебной строкой.** Проверка «ответ уже есть в
   ленте» смотрела на любую строку с тем же автором и тем же `reply_to`, а
   служебные строки координации туда попадали: роль «молчала», хотя её ответ
   ещё не пришёл.
5. **Часы в чатах считались по таймзоне устройства.** `ChatDayLabel`,
   `ChatMessageTime`, `ChatListTime` использовали `Calendar.autoupdatingCurrent`
   — вопреки общему правилу проекта (все даты в Europe/Moscow, независимо от
   устройства; `graft/moscow-timezone-enforcement.md`). «Сегодня» в чатах могло
   разъехаться с остальным приложением и с сервером.

## Что сделано

| Файл | Правка |
| --- | --- |
| `Sources/Core/Models/RoleChat.swift` | Новый `RoleChatRowID`: своя строка на каждое сообщение (`msg:<id>`), живой ход — `turn:<playbackID>`, а сообщение, закрывшее ход, занимает строку хода. `RoleChatMessageOrder.inserting(_:into:)` — вставка по серверному порядку (`sequence` = rowid) без полной пересортировки; общий компаратор для `sorted` и вставки. `RoleChatTime.date` — кэш разбора дат (NSCache), как в `ChatDayLabel`. |
| `Sources/Features/Chat/RoleChatsScreen.swift` | `feedItemID` — через `RoleChatRowID` и карту `rowIDByMessageID`; `visibleMessages` — прячется ровно то сообщение, которое закрыло ход (`completedMessageIDByTurn`); вставка вместо полной сортировки; живой ход не подавляется служебными строками (`hasAnswer(on:from:)`); своё отправленное сообщение занимает строку пузыря «в пути»; `ChatListTime` — московские часы. |
| `Sources/Features/Chat/ChatFeedMarks.swift` | `ChatDayLabel` и `ChatMessageTime` — московский календарь и часы. |
| `Tests/RoleChatTests.swift` | `RoleChatFeedIdentityTests`: уникальность id строк при шести ответах на один вопрос (и фиксация прежней формулы, совмещавшей все шесть), строка завершённого хода, вставка по `sequence`, замена известного сообщения на месте, равные секунды. `ChatDayLabelTests.testDayBoundaryIsMoscowNotDevice` — граница суток московская. |

## Ограничения (не сделано, блокеры)

- **Физический iPhone не установлен.** Сборка под устройство падает на
  подписи: `codesign … TaskFlowWidgets.debug.dylib: errSecInternalComponent`.
  Проверено вручную: подпись ЛЮБОГО файла тем же идентификатором
  (`Apple Development: inet2938@mail.ru`) падает с той же ошибкой — на маке
  после перезагрузки не открыт ключ (нужен пароль владельца). Это не связано
  с правкой: виджет-расширение я не трогал. Проверка на телефоне ждёт
  владельца.
- **Прокрутка ленты не переписана.** В `RoleChatsScreen` работают три
  перекрывающихся механизма: `defaultScrollAnchor(.bottom, for: .alignment/
  .sizeChanges)`, распорка `readingSpacer` и ручной `scrollTo` к своему
  сообщению с долей 0.38. Прыжок ленты объясняется в первую очередь
  пересозданием строк (пункт 1) — оно устранено. Остаток трёх механизмов
  разбирать отдельной правкой, с замером на устройстве: без телефона эту
  часть трогать опасно.
- **Сервер не трогал.** `GET /api/chats/:id/messages` отдаёт всю историю без
  `LIMIT`, а `formatChatMessage` делает по несколько запросов на каждое
  сообщение (`sequence`, `reply_to_sender_name`, реакции, checklist, вложения).
  На чате в 70 сообщений это ~350 запросов на открытие. Правка понятна
  (один `rowid AS sequence` в SELECT + батч остальных), но файлы
  `server/src/lib/chatMessages.ts` и `server/src/lib/chatChecklist.ts` в живом
  дереве принадлежат пользователю `tfrole`, а у меня нет прав на запись —
  трогать пришлось бы через подмену файла. Не делал; вынес владельцу.

# Живая разметка хода сессии — по сессии и ходу, не по тексту

14.11.2026, `LOCK-SESSION-LIVE-SCOPE-20261114`.

## Зачем

Живой ответ нового хода печатается кусками блоков сервера: `RoleLiveTextPacer`
режет реплику по `ChatLiveBlock.source`, экран рисует каждый кусок той же
подготовленной разметкой, что комната роли. Куски лежат в общем
`ChatLiveBlockRegistry`, и до этой правки реестр искал запись **только по
тексту реплики**:

- `register(_:for:)` чистил все записи с таким текстом;
- `blocks(for:)` брал последнюю запись с таким текстом;
- `block(startingWith:)` шёл по всем записям и брал любой блок, чей `source`
  начинается с показанного текста.

Значит два хода с одинаковым началом ответа («Сводка готова.») доставали чужие
блоки: ответ одной сессии рисовался разметкой другой. Сессия живёт долго, а
ходов в ней много — одинаковых ответов (приветствие, повторный запуск, две
параллельные сессии) хватает.

## Что сделано

1. **Область записи.** `ChatLiveBlockRegistry` хранит `(text, scope, blocks)`.
   Ключ — текст **и** область; запись без области видна только запросу без
   области. Поэтому чаты ролей и история (они область не передают) работают
   ровно как раньше, байт-в-байт.
2. **Идентичность хода.** `ChatLiveBlockScope.session(_ sessionID:
   turnStartedAt:)` = `sessionID + ":" + (startedAt.ISO8601Format() ?? "live")` —
   та же строка, что `RoleChatLiveTurn.startedAt`. `SessionLiveTurn` помнит
   `sessionID`, отдаёт `scope` и пишет разметку с ним; `SessionViewModel`
   передаёт `event.sessionId` и ставит `liveTurn.sessionID` в `installSnapshot`.
3. **Сквозной проброс.** `OwnerSessionScreen` → `SessionLiveTurnBubble` →
   `SessionLiveItemsList` → `SessionLiveItemsContent` → разметка, окно
   размышлений, шторка размышлений и пейсер (`RoleLiveTextPacer.ingest(_:
   isFinal:scope:)`, `pacingParts(_:scope:)`). У ролей область по умолчанию
   `nil`.
4. **Кэш кусков.** Второй канал смешивания нашёлся по ходу: `segments(
   fromServer:key:)` кэшировал разбор по ключу `"live:" + source`. Тот же текст
   с другим блоком (документ против виджета) попадал в готовую запись соседа.
   Теперь ключ — `ChatRichContent.liveCacheKey(_:)`: тип блока (и его размеры
   или хеш значения) плюс исходный кусок.

`test_role_chat_live_slots`, `test_server_document`, `test_server_only_render` —
зелёные; `Tools/design-system-guard.py --diff HEAD` — чисто; `swiftc -parse`
трёх затронутых вью — чисто.

переподключения — по прямому слову владельца. Симулятор, UI-тесты и установка
на iPhone не запускались; сборка Xcode не запускалась, потому что в этот момент

## 1. Что было сломано

Срок задачи — календарный день: на проводе это строка `YYYY-MM-DD` без
времени (spec/API.md §1), «сегодня» на сервере считается по `Europe/Moscow`
(сервер: `TASKFLOW_TIMEZONE`; клиент: spec/SCREENS-1.md §4.1). Клиент же
хранил срок как `Date` — момент времени — и переводил его в строку в трёх
разных зонах:

| Граница | Зона | Что было |
|---|---|---|
| значение по умолчанию в быстром добавлении | устройство | полночь «сегодня» телефона |
| пикер | устройство | дата отображается в зоне телефона |
| запись на сервер | Москва | дата по Москве |
| чтение с сервера | UTC | `YYYY-MM-DD` разбирался в UTC-полночь |
| «сегодня» для бейджа и списка | устройство | `DateFormats.todayString()` |

Инварианта «видимый день = сохранённый день» не было записано ни в одном
месте. Отсюда два симптома:

- **на телефонах восточнее Москвы (UTC+4 и дальше) дата уезжала на сутки
  назад**: выбрал 23 октября — сохранилось 22-е;
- **на телефонах западнее Москвы пикер показывал день, отличный от
  сохранённого** (UTC-полночь в зоне телефона — предыдущие сутки).

Плюс расходились два «сегодня»: бейдж таббара и `Task.isDueToday` считали по
устройству, подписи (`TaskDateText`, `TodayDate`) — по Москве.

Разбор и доказательство — у Архитектора (`docs/2026-10-22-task-day-zone-analysis.md`,
коммит `fae56fdc`), воспроизведение — у Аналитика (`6daa6b86`).

## 2. Что сделано

1. **Появился один владелец «дня срока»** — `Sources/Core/Common/TaskDay.swift`.
   Зона задачи — `Europe/Moscow`. Функции: `todayString`, `date(from:)`,
   `string(from:)`, `startOfDay`, `addingDays`, `instant(forPickerDay:)`,
   `pickerDate(forTaskDay:)`. Зона задачи и зона устройства передаются
   параметром — иначе поведение нельзя проверить без смены часового пояса
   телефона.
2. **Инвариант срока**: срок хранится **полночью дня в зоне задачи**.
   - чтение с сервера: `Task.dueDateAsDate` → `TaskDay.date(from:)` (Москва,
     а не UTC);
   - запись на сервер: `TaskFormViewModel.dueDateString` → `TaskDay.string(from:)`;
   - значение по умолчанию: `TaskDay.startOfDay(Date())` вместо полночи зоны
     устройства (быстрое добавление, «Сегодня» в форме);
   - пикер: показывается тот же календарный день, пересобранный в зоне
     устройства (`pickerDateForDisplay`), а выбранный день переводится обратно
     в зону задачи (`dueDateFromPicker`).
3. **«Сегодня» — по Москве в одном месте**: `Task.isDueToday` и бейдж
   таббара считают `TaskDay.todayString()`. Своя копия «сегодня по
   устройству» в `DateFormats` удалена.
4. **Попутный дефект в том же месте**: при **создании** задачи с телефона
   терялся повтор — в теле создания не было `run_repeat`/`repeat_until`
   (правка их шла). Поля добавлены в `APIClient.NewTaskRequest` и в
   `saveCreate`.

Вне объёма: сервер, веб, формат на проводе, миграции, уже сохранённые
неверные даты, экран «Мои рутины».

## 4. Ограничения

- Живая проверка на физическом iPhone и в симуляторе (смена часового пояса
  телефона) не выполнялась: в этом шаге проверялась логика и сборка.
  Сценарий на устройстве — за отдельным шагом «Живая проверка».
- Уже сохранённые неверные даты не исправляются: сервер не хранит зону
  клиента, массовая правка возможна только по догадкам.
- Приём `run_repeat`/`repeat_until` сервером при создании задачи не проверялся:
  исходников сервера на этой машине нет. Веб шлёт эти поля при создании,
  поэтому контракт должен совпадать.
- Для Берлина и Нью-Йорка поведение меняется: «сегодня» теперь считается по
  Москве — как на сервере и как требует спека клиента.

# Полноценная сессия помощника
27.10.2026. Владелец поручил соединить существующие части в одно управление сессией.

## Решение
Сессия — существующий отдельный чат, не новая параллельная сущность. Список, названия, архив, история, голос, контекст, рабочая папка и инструменты переиспользуются.
В чате помощника одна кнопка «Сессия» открывает панель: название и состояние, модель, доступные уровни размышлений (отключение только при поддержке), рабочая папка, контекст, навыки/инструменты, новая отдельная сессия и закрытие.
Настройки модели и размышлений сохраняются на сервере за chat_id; очередь получает снимок на момент сообщения. Смена настроек не переписывает уже отправленные поручения. Модель по умолчанию остаётся доступна. Смена модели сбрасывает несовместимый уровень в настройку роли.

## План реализации
1. RED: серверные тесты поддерживаемых уровней, валидации, изоляции сессий и снимка отправленного сообщения; macOS XCTest декодирования и разрешения уровня.
2. Сервер: каталог уровней из установленного Pi SDK; две небольшие таблицы настроек/снимков миграцией; GET/PUT preferences для личного чата помощника; чтение снимка в запуске Pi, включая resumed-сессию.
3. iPhone: серверные настройки в существующем ChatModelChoice, единая панель на готовых компонентах; существующий список сессий без перестройки. Новый разговор создаётся существующим API, старый остаётся.
4. Подсказка и проверка её хода; GREEN целевых тестов, статическая проверка Swift и сторож дизайн-системы.
5. Отчёт, собственные коммиты. Установка на iPhone и UI-тесты — только по отдельному поручению.

## Проверяемые границы
Нет выдуманных уровней или обещания количества запросов. Недоступный уровень отклоняется до запуска модели. Выбор не применяется к другим чатам. Открытие панели не запускает модель. Новая сессия не удаляет историю предыдущей. Переподключение использует существующий durable-механизм, новый исполнитель не создаётся.

## Реализовано
- В чате только с помощником кнопка «Сессия» заменяет разрозненные кнопки модели, папки и контекста. Панель использует готовые формы выбора папки, контекста и команд.
- Название, состояние, модель, размышления, папка, контекст и инструменты собраны вместе. Выбор команды вставляет её в исходный композер; сам выбор не запускает работу.
- Новая сессия создаёт отдельный чат существующим API и открывает его. Старый разговор остаётся в существующем списке; закрытие использует существующий архив.
- Модель и размышления хранятся в chat_session_preferences. Предыдущий выбор модели на устройстве переносится один раз, только если серверные настройки ещё не были сохранены.
- На принятом сообщении сохраняются модель и снимок размышлений. Следующее изменение настроек не переписывает очередь.
- Уровень применяется и при создании Pi-сессии, и поверх уровня восстановленной сессии. Сжатие также использует настройки сессии.
- Повторный выбор модели ничего не сбрасывает; совместимый уровень сохраняется. Несовместимый уровень сбрасывается в настройку роли.
- Список уровней берётся из установленного SDK. Для известного Ollama/Qwen не показывается ложный off; настроенный провайдером minimal→none подписан «Выключены». У Gemini 3 off не предлагается, поскольку адаптер заменяет его низким уровнем.
- Изменять настройки может только человек-владелец, не помощник под делегированными правами владельца.

## Проверки и ограничения
- Новый тест реального запуска: до правки SDK получал max вместо выбранного low (RED); после правки получает low, восстановленный уровень также заменяется (GREEN).
- Настройки, изоляция, неподдерживаемые уровни, HTTP-снимок, сохранение совместимого уровня, настройки сжатия и права помощника: 12/12.
- Регрессия общего каталога/голосового контекста вместе с первым набором настроек: 30/30; дополнительный тест запуска Pi: 1/1.
- macOS XCTest: 4 теста модели настроек и 1 тест нового сценария подсказки — 5/5, без симулятора.
- TypeScript --noEmit / компиляция: PASS. Изменённые Swift-файлы прошли синтаксический разбор. xcodegen выполнен, новые файлы включены в проект. Сторож дизайн-системы чист.
- Общий старый chat-session-runtime: 11 падений, тот же состав на baseline; новый тест исправления на baseline падал дополнительно. Общие подсказки: 2 прежних падения — testOwnMessageCopyHintCompletes и testWebhookHintExplainsGenericReceiverAndOptionalCodexBranch, подтверждены на исходных HintScenarios/тестах из HEAD.
- Полная сборка приложения, симулятор, UI-тесты, установка и визуальная приёмка iPhone не выполнялись. Фактическая экономия токенов живой моделью не измерялась.

## Сервер
Перед применением очереди пусты, активных attempts и голосовых комнат нет. Ранее собранный baseline совпал с рабочим dist для всех заменяемых старых модулей: чужих изменений в выкладке нет.
Бэкап: /home/maksim/.local/state/taskflow-backups/assistant-sessions-20261027.
Применены только изменённые JS-модули и новые модули настроек; taskflow-server.service перезапущен.
Проверки живого сервера: /api/health — 200; чтение session-preferences — 200; каталог помощника — 200, 160 моделей с метаданными уровней; миграция 183 применена. Модель при этих проверках не запускалась, настройки живых разговоров не менялись.

## Приёмочный сценарий владельца
После отдельной установки на iPhone: открыть разговор помощника → «Сессия» → выбрать модель и доступный уровень → отправить поручение → выйти и снова открыть разговор → проверить сохранённый выбор. «Новая сессия» открывает отдельный пустой разговор, прежний остаётся в списке. Этот сценарий владельцем пока не пройден.

# Изменения кода в карточке задачи — 27.10.2026

LOCK-TASK-CODE-CHANGES-20261027.

## Цель

Владелец: «точно буду знать, что трогали, что не трогали; когда вижу, что
какое-то поведение не так, всегда смогу это увидеть». В карточке видно, что
роль поменяла в своей ветке `roles/<task_id>`, и можно оставить замечание
к конкретной строке.

## Что сделано

**Сервер (.110, коммит `8979d069`).**
`GET /api/tasks/:id/code-changes`: только владелец, только чтение.
- Ветка не влита: показывается diff от точки ответвления от `main` до вершины
  ветки, то есть только работа роли, без того, что ушло в `main` позже.
- Ветка влита: диапазон `main_sha_before..result_sha` из `worktree_merge_queue`.
- Ветки нет: `state: "none"`, пустой список.
- Diff разбирается на сервере (`server/src/lib/worktree/codeChanges.ts`):
  файлы, статусы (новый, удалён, переименован), счётчики +/−, строки с номерами.
  Потолок 2000 строк на файл (`truncated`).
- vitest `server/test/codeChanges.test.ts`: 6/6. До модуля тест падал
  (модуль не найден), после — зелёный. `tsc --noEmit` чистый.

**iOS.**
- «Итог» → строка «Изменения кода · 3 файла · +42 −7» (`TaskCodeChangesRow`).
- Шторка со списком файлов: имя, путь, пометка статуса, +/−.
- Файл одной колонкой: «−» красным, «+» зелёным, между кусками правки —

  «Отправить роли» уходит одним комментарием карточки с файлом, строкой и кодом.
  Роль читает комментарии при следующем запуске.

## Чего нет и почему

- **Кнопки «Принять».** Вливание в `main` идёт через очередь слияний с прогоном
  тестов. Прямое вливание из приложения обходило бы эту защиту.
- **Незакоммиченное в рабочей копии роли** не показывается, только коммиты ветки.
- **Только репозиторий сервера** (`liveRepo()`). Ветки ролей в других
  репозиториях этот запрос не видит.

## Что осталось

- Маршрут заработает после выкладки сервера. Её делает `taskflow-deploy-idle`,
  когда роли затихнут. На момент коммита сервер ещё отвечал 404.
- Внешний вид не проверялся — его оценивает владелец на iPhone.

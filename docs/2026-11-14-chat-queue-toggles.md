# Тумблеры очередей чата — 14.11.2026

## Что сделано

Владелец 14.11.2026: первую очередь отложенных сообщений временно отключить, оба поведения
очередей вывести тумблерами в настройки, чтобы пробовать «как лучше»; плашка «В очереди»
в ленте ему мешает.

Сервер (`New-Todoist`, коммит `a59d9a32`):

- `server/src/lib/serverSettingsRegistry.ts` — новая группа `чаты` и два `bool`-параметра:
  - `chat_queue_defer_enabled` — «Откладывать сообщение, пока роль отвечает»;
  - `chat_delivery_journal_enabled` — «Журнал доставки ходов чата».
  Оба по умолчанию `true` — поведение прежнее, пока владелец не выключит.
- `server/src/routes/chats.ts`:
  - постановка в `chat_queued_messages` идёт только при включённом `chat_queue_defer_enabled`;
  - при выключенном `chat_delivery_journal_enabled` ход не пишется в `chat_message_queue`:
    fence, закрытие и удержание выполняются через локальные обёртки, которые ничего не
    делают без журнала.
- `server/src/lib/chatMessages.ts` — `queue_delivery_state` не отдаётся при выключенном
  журнале, поэтому плашка доставки в ленте не рисуется.
- `server/src/lib/chatQueueToggles.test.ts` — метаданные группы и дефолты, vitest 3/3.

Клиент (iOS, эта ветка): `Sources/Core/Networking/APIClient+ServerSettings.swift` —
группа `чаты` в порядке рендера; `Sources/Features/Settings/ServerSettingsScreen.swift` —
подпись раздела «Чаты». Тумблеры рисует существующая форма по `kind: "bool"`.

## Как включить/выключить

Настройки → Сервер → Параметры → раздел «Чаты». Значение применяется на следующий ход,
перезапуск сервера не нужен.

## Ограничения

- Журнал при выключении не защищает от дублей и от потери хода при перезапуске сервера —
  это сознательный выбор владельца на время эксперимента.
- Значения по умолчанию включены: чтобы «отключить первую очередь», владельцу нужно
  переключить тумблер в настройках после выкладки сервера.

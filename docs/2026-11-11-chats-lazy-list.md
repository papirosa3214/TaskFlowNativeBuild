# Чаты: переход в чаты роли без задержки списка и поля поиска

Дата: 11.11.2026. LOCK-CHATS-LAZY-LIST-20261111. Реестр: `AGENT-WORK-SCOPES/2026-11.md`.

## Что сказал владелец

«Получается при переходе из чатов в чаты роли идёт задержка с появлением этого
списка ну этого поля ввода» (11.11.2026). Прошлая правка `649f627` убрала чтение
GRDB с главного потока — задержка осталась, значит дело не в базе.

## Причина

`RoleChatsScreen.chatScroll` держал строки списка в обычном `VStack` внутри
`ScrollView`. Такой контейнер верстает **все** строки в первом же кадре, а не
только видимые. В боевой базе 216 чатов (и это подтверждено замером прошлой
правки), поэтому и push-переход, и появление штатного поля поиска в шапке
ждали вёрстку двух сотен строк.

## Правка

`Sources/Features/Roles/RoleChatsScreen.swift`: `VStack(spacing: 0)` →
`LazyVStack(spacing: 0)` в `chatScroll`. Ленивый контейнер строит только видимое,
остальное достраивается по прокрутке. Порядок строк, разделители, ветки, каталог
групп и выдача поиска не менялись — они остались теми же `ForEach` внутри.

## Проверки

- `python3 Tools/test_chats_lazy_list.py`: RED на коде до правки (обычный
  `VStack` в `chatScroll`) → GREEN после.
- `python3 Tools/design-system-guard.py --diff HEAD` — чисто.
- Замер в симуляторе: см. раздел ниже (обновляется по факту прогона).

## Ограничения

- Сборка, запуск в симуляторе и установка на iPhone — не зона роли по
  умолчанию; замер идёт только по прямому разрешению владельца от 11.11.2026
  («только замерь в симуляторе»).
- Вид экрана оценивает владелец: ленивый контейнер не меняет внешний вид, но
  прокрутка длинного списка теперь другая по механике (строки появляются по
  ходу), и это надо увидеть глазами.

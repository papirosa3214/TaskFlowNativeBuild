# Рутины: выбранный шаблон плана — 29.10.2026

## Согласованные границы

В форме «Исполнитель» открывает тот же системный Menu и тот же каталог, что
«Предложить план по шаблону» в карточке. Пункт «Автоматически» означает отсутствие
назначенного плана/роли, не builder по умолчанию. Создание, редактирование и
возврат к «Автоматически» должны сохраняться. Старое явное назначение роли
поддерживается при чтении и сохранении старой рутины. Старые планы не удалять.

## Фактический путь и план реализации

1. Общий каталог десяти шаблонов и содержимое Menu извлечь из TaskFormScreen;
   переиспользовать в форме рутины. `single_executor` остаётся существующим
   серверным шаблоном из одного шага. UI не требует нескольких исполнителей.
2. Добавить nullable `task_payload.plan_profile` в контракт рутины. Выбор
   шаблона очищает legacy assignee_id; «Автоматически» очищает оба поля явным
   JSON null (PATCH сервера объединяет поля и иначе сохраняет старые).
3. Сервер валидирует профили по существующему TEMPLATE_PROFILES при POST/PATCH.
   Шаблон хранится в task_payload JSON: миграция БД не требуется.
4. Только для явного legacy исполнителя или выбранного шаблона scheduler
   передаёт запрет автоподготовки при POST задачи. Добавить проверяемый boolean
   параметр создания задачи, доступный владельцу. Пустой выбор оставляет
   существующий код автоподготовки без изменений.
5. Для шаблона scheduler использует существующие /collaboration-plans/propose
   и /approve с полномочиями владельца рутины; роли и зависимости берутся из
   штатного шаблона. Legacy назначение использует startSingleExecutorPlan.
   Ошибки подготовки/утверждения отражаются в истории запуска.
6. Unit RED → GREEN: серверное создание задачи с/без suppression; tick с
   legacy ролью, single_executor, командным шаблоном и автоматическим выбором;
   POST/PATCH/очистка/отказ неизвестному шаблону. iOS — реальные модель формы
   и кодирование payload с API double; сценарий подсказки в HintCenter.
7. Проверки: целевые vitest --maxWorkers=4, TypeScript, macOS host units,
   Swift parse, дизайн-сторож. Без симулятора/UI-тестов/установки.
8. Сервер — отдельный worktree на .110 → PR → CI/automerge → маркер/health;
   iOS — свои файлы в main → push origin. Scope REVIEW, отчёт дополнить
   фактами проверки и ограничениями. Телефонная приёмка отдельно владельцем.

## Реализовано и проверено

- Общие `CollaborationPlanTemplate` и `CollaborationPlanTemplateOptions` используются
  обоими системными Menu. Каталог и серверные роли шаблонов не переопределялись.
- В рутине строка «Исполнитель» по умолчанию показывает «Автоматически».
  Этот же пункт меню снимает прежний шаблон или legacy роль. Сохранение доступно
  без назначения. Выбор шаблона очищает assignee_id, выбранный профиль сохраняется
  в plan_profile; оба nullable поля отправляются явно при очистке.
- Серверный `skip_auto_plan` — boolean-параметр POST задачи с проверкой прав
  владельца. Проверка стоит до обеих ветвей автоподготовки, включая JEV/подзадачи.
  Scheduler включает его только при role или plan_profile; при null/null
  автоподготовка остаётся прежней (включая возможность не создавать черновик,
  когда штатный подбор считает достаточным одного исполнителя).
- Scheduler для профиля вызывает штатные propose/approve от владельца рутины.
  Ошибки предложения/утверждения попадают в историю; сам запуск корневых шагов
  и его ошибки обслуживает штатный approve. Не вводится свой конвейер исполнения.
- В живой БД read-only обнаружена задача 9566c4b6-e63c-4475-9399-ec3ec2b4ab21
  из рутины с bug_regression/draft и single_executor/approved. Никаких изменений
  старых планов, рутин и задач при исследовании не делалось.

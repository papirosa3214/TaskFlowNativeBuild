# Pipecat: два экспериментальных режима голоса

Дата: 30.10.2026. Поручение: два режима для сравнения, текущий стек сохранить.

## Решение

Текущий LiveKit Agents + Gemini Live остаётся режимом по умолчанию. В настройках голоса — отдельный выбор режима следующего звонка, смена во время звонка невозможна.

1. `current`: прежний маршрут без дополнительного поля запроса.
2. `pipecat-live`: Pipecat + Gemini Live, прежние инструкции, история и общий каталог инструментов.
3. `pipecat-chat`: Pipecat, распознавание завершённой фразы Gemini, действующий исполнитель текстового чата, Gemini TTS. Без новой отдельной модели-исполнителя. Сохранение реплик без двойного запуска модели.

Из доступных сервисов используется уже настроенный Gemini; ключи не попадают в код и отчёт. Поставщики выбираются владельцем как «из доступных сервисов».

## Изоляция

Отдельное Python-окружение и именованный worker. Экспериментальные комнаты имеют собственный префикс. Текущий worker отклоняет только такие комнаты, обычные принимает прежним способом. Сервер не выдаёт экспериментальный токен при выключенном эксперименте. Неизвестный режим — ошибка, а не молчаливая подмена. Ошибка Pipecat не переключает текущие звонки и не повторяет поручения.

Рассмотрены: глобальная замена worker (отклонена: нарушает сохранность текущего стека), второй LiveKit сервер (лишняя инфраструктура), отдельный именованный worker на существующем LiveKit (выбран мной: сохраняет транспорт iPhone и отделяет зависимости).

## Проверки и сравнение

- RED → GREEN: выбор/маршрутизация, отключённый эксперимент, неизвестный режим; default не меняет прежний запрос.
- Общий исполнитель: проверка владельца и чата, идемпотентность, ответ связан с исходной фразой, повтор не запускает второй ход.
- Целевые Python и серверные unit-тесты, Swift host-тесты без симулятора, parse, дизайн-сторож.
- Отдельные синтетические аудио-проверки: русская фраза, ответ, инструменты, прерывание, сохранение истории. Они не заменяют владельческий звонок с iPhone.
- Базовый сценарий приёмки: обычный звонок; оба эксперимента; прервать ответ; два звонка подряд; продолжить переписку; свернуть приложение. Экран проверяется отдельно для каждого режима, без обещания одинаковых возможностей заранее.

## План

1. Тесты и маршрутизация на сервере, отдельный worker и мост к исполнителю чата.
2. Изолированный Pipecat pipeline каждого режима, история, инструменты, завершение и interrupt.
3. iOS: режим следующего звонка в настройках голоса, подсказка; default без изменений.
4. Целевые проверки, PR сервера, доступность эксперимента и инструкция сравнения. Сервисы не перезапускать во время активных звонков/ходов; перед серверной выкладкой резервная копия БД.

## Результаты

В работе. Наличие кода или успешный импорт не считаются готовым голосовым разговором.

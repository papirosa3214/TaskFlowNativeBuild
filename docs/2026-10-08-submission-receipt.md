# Подтверждение сдачи этапа основным TaskFlow

Дата: 08.10.2026. Карточка: 8aa62aea-8522-4400-af10-73a01b0a6ce0.

## Результат

Инструмент сдачи отдельно перечитывает серверную квитанцию после сохранения результата. Успех возвращается только если основной сервер подтверждает закрытие нужного этапа и сохранение конкретного артефакта. Тестовая QA-копия отклоняет сдачу рабочих этапов.

В карточке этапа видны «Сдача подтверждена сервером», время UTC, ID артефакта и ссылка «Отчёт о работе». Текст результата без подтверждения сервера сопровождается пометкой «Сдача основным сервером не подтверждена».

## Что сделано

- GET `/api/subtasks/:id/submission-receipt` проверяет сохранённый результат и закрытый этап, с существующей проверкой доступа.
- Квитанция содержит confirmed, authority, task_id, subtask_id, artifact_id, document_id, confirmed_at; возвращается также в графе.
- taskflow_subtask_done на внутреннем runtime и Python MCP повторно читает квитанцию. Ошибка, другой этап, другой артефакт или authority=sandbox не дают успешной отбивки.
- Структурная сдача, обычное закрытие этапа и финальный вердикт роли защищены в QA-копии; копия базы с ранее принятым результатом также не выдаёт подтверждение основного сервера.
- Запуск QA-копии требует наличия защиты в её исходнике; старую ветку без защиты нужно сначала обновить.
- Инструкция запуска роли закрепляет сдачу штатным инструментом и ожидание подтверждения. Предварительная приёмка владельца или следующей роли не добавляется.
- Старый результат QA v3 не переносился и не выдаётся за проверенный заново.

TypeScript, синтаксис Python и bash проверены.

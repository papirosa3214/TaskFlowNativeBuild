# Ответ на уточнение подготовки

В окне «Подготовка» под вопросом появилась кнопка «Ответить». Для вопроса о выборе между дочерними карточками, планом ролей и одной карточкой с подшагами открывается три готовых варианта; нажатие отправляет выбранный ответ без клавиатуры. Для иных вопросов оставлено поле свободного ответа: одинаковые три варианта нельзя подставлять к вопросу о неизвестном адресе API или материале. Универсального структурированного списка ответов текущий сервер не возвращает.

Ответ дописывается к актуальному описанию карточки вместе с исходным вопросом через существующий PATCH задачи. Это тот вход, который реально читает autoPreparation. Правка описания запускает новый прогон подготовки. Отдельный retry не вызывается: он разрешён сервером только после failed. Название, проект, роли и состояние задачи этот запрос не меняет.

Перед записью проверяются id/input_version/status и сам вопрос последней подготовки. Пустой ответ отклоняется без HTTP-запросов. При ошибке окно сохраняет ответ; повторная отправка заблокирована на время запроса. Обычный PATCH описания не поддерживает атомарный If-Match: одновременная правка описания другим клиентом между чтением и записью остаётся ограничением текущего API.

## Отдельный живой сбой
Карточка «Серверный журнал событий и API диагностики», e87cd93f-5026-4f15-9db1-feb1cb241cdb. Прогон 343 запросил выбор формы подготовки. В прогоне 344 зафиксирована ошибка «Неизвестная или выключенная роль»; на момент чтения status=queued, attempts=1. Источник сообщения — validatePreparation, проверка workstream.role по enabledRoles. Эта задача меняет интерфейс ответа; серверный сбой назначения роли не исправлялся. Боевую карточку тесты не меняют.

## Проверка
Используется изолированный HTTP/WebSocket API на 127.0.0.1:3307. UI-тест открывает карточку → «Ещё» → «Подготовка» → «Ответить», проверяет три кнопки и отсутствие поля ввода, выбирает план ролей и ждёт «Готовится».

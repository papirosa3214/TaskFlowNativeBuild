# Управление из окна координации (02.11.2026)

## Задача

Владелец открыл «Координацию» у задачи, которая уже выполняется, и сказал:

> «я просто что-то вижу, но по факту не могу ничего как-то управлять этим процессом»

Узлы графа показывали состояние шага (причина, ожидание, исполнитель), но не давали
ни ответа на вопрос «кто это делает и чего ждёт», ни способа вмешаться. Окно было
наблюдательным.

## Что стало

### 1. Окно исполнителя — по тапу на узел графа

Тап по узлу графа открывает шторку «Исполнитель» (`Sources/Features/Coordination/ExecutorWindow.swift`):

| Секция | Что показывает |
|---|---|
| Шаг | Название шага, состояние плашкой («Идёт работа», «Ждёт вас», «На проверке»), очередь ожидания, заметка сервера, счётчик непрочитанных исполнителем сообщений |
| Исполнитель | Роль и её название, состояние, начало и итог активной попытки, число попыток за окно, причина, по которой написать нельзя |
| Ждёт вашего ответа | Вопросы роли с вариантами ответа — ответить можно прямо отсюда |
| Переписка по шагу | Что владелец писал этому шагу и что роль отвечала |
| Написать исполнителю | Поле ввода и отправка — см. ниже |
| Переписка по задаче | Открыть тему задачи целиком |

Всё приходит с сервера человеческим текстом: телефон ничего не разбирает
(правка владельца 02.11.2026 — тот же принцип, что в PR #52 «JSON-слот →
человеческий текст»).

### 2. Секция «Управление» в окне координации

- **«Написать оркестратору»** — открывает окно исполнителя слота оркестратора
  (`slot_key=orchestrate` у orchestrated-плана). Кнопка появляется, только если
  такой слот есть: нечего адресовать — не показываем.
- **«Переписка по задаче»** — открывает тему задачи, где видны ответы всех
  исполнителей.

Раньше из координации можно было только перезапустить шаг.

## Как доходит сообщение до исполнителя

Механика серверная, клиент по ней ходит так:

1. Клиент берёт тему задачи: `POST /api/tasks/:taskId/topic`.
2. Отправляет сообщение в тему: `POST /api/chats/:chatId/messages` с
   - `execution_mode: "card"` — сообщение идёт в работу слота, а не в общий чат;
   - `recipient_subtask_id` — адресат-шаг;
   - текстом, начинающимся с упоминания роли (`@Название роли`).
3. Сервер (`server/src/routes/chats.ts`):
   - `dispatchRoleReplies` поднимает роль по упоминанию;
   - `resolveTopicSlot` находит слот по адресату;
   - `deliverTopicToWork` подмешивает сообщение в текущий ход роли, если она
     занята этим шагом, или кладёт его в инбокс слота, если ход ещё не начался.

**Условие, найденное при разведке:** роль поднимется, только если её слот —
настоящий узел утверждённого плана (`topicSlots` = слот + узел плана + план в
статусе `approved`). Шаг без плана адресации не поддаётся. Это зафиксировано
тестом `server/test/coordination/addressSlot.test.ts` (PR #54).

Упоминание роли нужно потому, что в групповой теме сообщение без `@` остаётся
просто текстом в ленте — роль не просыпается.

# Метка даты заведения в строке задачи

12.10.2026 · LOCK-TASK-CREATED-STAMP · opencode

## Что просил владелец

Дословно, по ходу разговора:

> «мне нужна дата и время заведения этой заявки, ну, попадание этой заявки
> в этот проект, чтобы отражались вот эти вот вещи»

> «мне только числа нужны… 12.10.2026, дефис, там, я не знаю, ну или и время,
> там, 13, двоеточие, 10, и все это в квадратных скобках»

> «увеличить шрифт наименования задачи» (добавлено по ходу работы)

Шрифт: «используй какой-нибудь… прикольный… пиксельный». Показано восемь
вариантов кадрами в настоящей строке списка, выбран **DotGothic16**.

## Формат

`[12.10.2026 - 13:10]` — только цифры и знаки, ни одного слова. Квадратные
скобки обрамляют. Вариант со словами («заведена 12 окт») владелец отверг
прямо.

## Где показывается

| Экран | Файл |
| --- | --- |
| Список задач проекта | `DirectoryTaskRow.swift` |
| Метки | `LabelTasksScreen.swift` |
| Сегодня | `TodayTaskRow.swift` |
| Планирование (список и день) | `UpcomingTaskRow.swift` → `TFTaskRowModel` |
| Поиск | `SearchScreen.swift` → `TFTaskRowModel` |

Метка рисуется в общем компоненте `TFTaskRowContent`, то есть одинаково во
всех списках. Пустой даты не бывает — вью не создаётся вовсе.

## Данные

`tasks.created_at` — сервер отдаёт его в `/api/tasks` уже сейчас (`TASK_COLUMNS`
= `t.*`), клиент декодировал и раньше (`ApiTask.createdAt`), просто нигде не
показывал. Серверная часть для этого не требовалась.

**Время московское**, не таймзона устройства: `created_at` приходит из SQLite
в UTC, и та же трактовка уже принята для подписей уведомлений
(`DirectoryDate.absolute`). Иначе заведённая ночью задача «уезжала» бы на день
при смене телефона.

### Чего НЕ сделано и почему

Вторую метку — **попадание заявки в проект** — сделать нельзя: сервер такого
не хранит. В таблице `tasks` нет такой колонки (проверено на живой базе
`.110`: 59 колонок, среди них только `project_id` и `project_name_snapshot`),
в журнале `task_events` нет события (`field_changed` бывает только по
`title`, `due_date`, `assignee_id`, `machine_selected_role`). 163 задачи с
проектом, момент входа в проект не зафиксирован нигде.

Нужна отдельная серверная карточка: миграция `project_assigned_at` с
заполнением при создании задачи и при смене проекта, плюс отдача в
`/api/tasks`. Бэкенд и веб лежат в другом репозитории (`New-Todoist` на
`.110`), натив туда по правилам проекта не кладётся.

## Шрифт

DotGothic16 (OFL 1.1). Оригинал — 2 МБ, 8231 глиф; урезан до ASCII + кириллицы
+ `№` → **61 КБ**. Хинтинг сохранён: на 11 pt пиксельный шрифт без него мылится.

Три места, где это надо было проверить, и два из них были ловушками:

1. **`UIAppFonts` не в `Resources/Info.plist`.** xcodegen **генерирует** plist
   из секции `info.properties` в `project.yml` и молча затирает файл — первая
   правка plist пропала целиком, шрифт в бандле лежал, а ключа не было.
   Обнаружил тест на регистрацию шрифта, не глазами.
2. **`Font.custom(_:size:)` не масштабируется** под Dynamic Type. Свой
   `@ScaledMetric(relativeTo:)` — иначе строка задачи не проходит WCAG 1.4.4.
3. Шрифт в бандле сам по себе не гарантирует отрисовку: имя в `UIAppFonts`
   — это PostScript-имя из name-таблицы TTF.

## Попутно исправлено

1. **Метка обрезалась.** В тесных строках дата доезжала огрызком
   (`[12.10.20…`) — обрезанная метка читается как дефект, а не как время.
   `fixedSize(horizontal: true, vertical: false)`: остальные элементы
   мета-строки сжимаются первыми (у них `layoutPriority(-1)`), дата остаётся
   целой.
2. **Метка не доставалась VoiceOver в «Сегодня».** Строка собрана
   `accessibilityElement(children: .ignore)` с подписью из одного названия —
   всё содержимое, включая метку, заменялось этой подписью. Дата была видна
   глазами и **не существовала** для VoiceOver. Дописал в
   `rowAccessibilityLabel` словами («Заведена 12 октября в 13:10») — пиксельные
   цифры VoiceOver как дату не читает.
3. **Название задачи 15 → 17 pt** (просьба владельца). Правка в
   `TFTaskRowContent` — сразу во всех списках. Свой `@ScaledMetric`, а не
   новая ступень `TFTextStyle`: добавление кейса задевало бы общий файл
   типографики и его 342 вызова.

## Проверка

| Что | Результат |
| --- | --- |
| `xcodegen generate` + сборка iOS Simulator (iPhone Air, iOS 27) | BUILD SUCCEEDED |
| `TaskFlowTests/TaskCreatedStampTests` | 10/10 PASS |
| `TaskFlowUITests/TaskCreatedStampUITests` | 2/2 PASS (iPhone Air симулятор) |
| Установка на физический iPhone | BUILD SUCCEEDED, установлено, запущено обычным запуском |

UI-тесты идут на **живом сервере** `.110` — не на фикстуре: элементы ищутся по
`accessibilityIdentifier`/`label`, кадр — `XCTAttachment(screenshot:)`,
выгрузка — `xcrun xcresulttool export attachments`. Кадры в
`docs/2026-10-12-task-created-stamp/`.

Юнит-тесты закрывают то, что XCUITest на текущих данных не достаёт: границу
суток UTC→МСК (задача, заведённая в 23:30 МСК, приходит как `20:30 UTC` того
же дня и обязана остаться 12-го), полночь МСК, отсутствие букв в метке,
пустые значения и регистрацию шрифта в бандле.

### Не проверено

- **Список «Сегодня» на живых данных.** Задача со сроком там одна (срок
  11.10), и в списке «Сегодня» она не появляется — `TASKFLOW_DEBUG_ROUTE=today`
  открывает месяц планирования, где задача видна плашкой на 11-м числе.
  Кадр оттуда снять не на чем; проверку подписи VoiceOver унесли в юнит-тест.
- **Физическая приёмка на iPhone глазами владельца.** Приложение собрано,
  подписано, установлено и запущено; сам вид метки на настоящем экране
  телефона не снимал — это к следующему шагу по решению владельца.
- Метка в списке задач агента («Работа агентов») и в «Архиве» не проверялась:
  обе строки идут через `DirectoryTaskRow`, метка там есть, но данных для
  кадра я не гонял.

## Грабли, которые стоит помнить

- `AGENT-WORK-SCOPES.md` правится через правку существующей строки, а не
  создание дублей Lock ID: в файле уже есть `LOCK-PROJECTS-LIBRARY-FOLDER-…`
  и `LOCK-PROJECTS-QUICK-ADD-…` с одним Scope ID — придумывать новый ID ради
  двух правок в один экран не нужно.
- xcodegen перезаписывает `Resources/Info.plist` по `project.yml`. Любой ключ,
  добавленный прямо в plist, исчезает без предупреждения.

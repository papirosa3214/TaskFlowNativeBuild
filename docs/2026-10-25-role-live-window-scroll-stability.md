# Окно роли: прокрутка не уезжает наверх, обновления не перезапрашивают снимок

25.10.2026. Продолжение правки `d012eb15` (локальный `main`): якорь вложенной
прокрутки уже убран, но два пути обновления продолжали дёргать окно и сеть.

## Что было не так

1. `TaskLiveActivityView` и `AgentTraceView` привязывали REST-снимок к ревизиям
   живых событий (`realtime.revision`, `realtime.activityRevisions`). Во время
   хода события идут примерно раз в секунду — значит, задача перезапускалась
   каждый раз, уходил запрос `/live` (и `/activity`), а содержимое окна
   перерисовывалось. Прокрутка внутри окна при этом уезжала наверх.
2. В `main` уже стоял троттлинг «не чаще раза в 2 секунды», но он был сделан
   через `.task(id: activityRevision)`: смена id отменяет предыдущую SwiftUI-задачу
   (Apple: «If the id value changes, SwiftUI cancels and restarts the task»).
   При событиях чаще раза в две секунды ожидание постоянно отменялось — список
   действий мог не обновляться вовсе.

## Что сделано

- Новый тип `LiveActivityRefreshState` (`Sources/Features/Task/Detail/`):
  событие активности только помечает список протухшим, а забирает его цикл не
  чаще раза в `minimumInterval` (2 секунды). Флаг протухания переживает паузу:
  событие во время интервала не теряется, а ждёт следующей проверки.
- `TaskLiveActivityView`: снимок берётся только при открытии окна, смене шага и
  смене сцены; список действий обновляется отдельным циклом; события активности
  больше не перезапускают задачу.
- `AgentTraceView`: то же самое для ленты хода. Живой ход по сокету
  (`tasks:live`) применяется локально, как раньше; REST-догоняющая выборка
  действий выполняется только когда живого хода для этого шага нет.

## Чего не сделано

- Один WebSocket на экран не сведен: `RealtimeClient` держит единственный
  слот `onEvent`, который занимает приложение (`TaskStore`), поэтому
  перевести виды на общий канал — отдельная правка с много подписчиками.
- Установка на физический iPhone не выполнялась — по правилу проекта это
  отдельное поручение владельца.
- UI-тесты не запускались: по прямому указанию владельца от 24.10.2026 их нельзя
  писать и запускать без отдельного согласия.
- Скриншот шторки роли снять не удалось: симулятор открывает карточку по
  `TASKFLOW_DEBUG_ROUTE=task:<id>`, а сама шторка роли требует тапа по узлу
  графа; инструмента тапа по accessibility в этой сессии нет. Вместо кадра —
  измерение журнала сервера и unit-проверки.

## Как проверить на устройстве

1. Задача с планом совместной работы → узел роли «Разработчик» → раскрыть
   «В работе» → прокрутить к «Прервать» и подождать 10 секунд.
2. Ожидание: позиция не меняется, кнопка достижима, список действий и живой
   текст продолжают обновляться.
3. В журнале сервера (`server/dev-server.log`) за 30 секунд на телефоне:
   `GET /api/tasks/:id/live` — только при открытии, а не на каждое событие;
   `GET /api/tasks/:id/activity` — не чаще одного раза в две секунды.

# Чаты: задержка поля поиска при переходе

Владелец 11.11.2026: «наверху есть поле ввода поиска, и при переходе на эти
экраны [чаты ролей]… задержка какая-то идёт».

## Причина

Поле поиска — штатное `.searchable(placement: .navigationBarDrawer)` в
`Sources/Features/Roles/RoleChatsScreen.swift:124`. Само оно быстрое. Вставал
не поиск, а экран: при открытии список читал **локальную базу GRDB прямо в
главном потоке** — `load()` и `refreshList()` вызывали
`LocalStore.shared.chats(...)` / `upsertChats` / `hideChats` / `syncState`
синхронно. Плюс дисковый `ResponseCache` (`api.cachedRoleChats`,
`api.cachedChatRooms`) — тоже чтение файла в главном потоке.

Нагрузка живая: в боевой базе на .110 **216 чатов** у владельца и **2724
сообщения**; чтение списка с разбором JSON и уборкой лишних строк — заметное
время. Всё это шло в том числе при переходе с главного экрана чатов в чаты
роли, и анимация перехода вместе с появлением поля поиска ждали базу.

Чтение/запись вне главного потока — требование проекта:
`Sources/Core/Store/LocalStore.swift:18` прямо говорит, что класс не
`@MainActor` и `DatabaseQueue` безопасна из любых потоков.

## Что сделано

`Sources/Features/Roles/RoleChatsScreen.swift`:

- `localChats(includeClosed:)` — чтение списка из базы в `Task.detached`.
- `localETag()` — отпечаток списка оттуда же.
- `storeChats(_:keeping:etag:)` — upsert, уборка лишнего и запись отпечатка
  одной фоновой задачей.
- `hideLocalChat(id:)` — архив/удаление пишут в базу в фоне.
- `cachedChats(includeClosed:)` / `cachedRooms()` — дисковый кэш ответов
  читается в фоне.
- `load()` и `refreshList()` ждут эти функции через `await`; порядок и
  поведение (база → кэш → сеть, 304, уборка лишних чатов) не менялись.
